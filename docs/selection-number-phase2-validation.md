## 실행과 계측

macOS arm64, Python 3.13.18, SQLite 3.53.1의 동일 머신에서 격리 `settings_test` DB와 같은 Fixture를 사용했다. 각 경로의 워밍업 1회 뒤 5회 중앙값을 기록했다. SQL 수는 타이밍과 별도의 실행에서 `execute_wrapper`로 집계했다. Enemy·NPC·Door와 Corpse·Ground 혼합 경로의 대상 수는 각 유형별 개수다. 예를 들어 100에서 전자는 300개, 후자는 200개다. 실측값은 대표 Fixture의 결과다.

```sh
.venv/bin/python scripts/dev.py test tests.bench_selection_phase2 --parallel 1
```

표의 각 셀은 1 / 10 / 100개 순서다.

## Issue #112 총기·조명 웹 Action Control

기준은 `0155f7092e61f910ce4fc94b55f4db70383f6124`다. macOS arm64, Python 3.13.18, SQLite 3.53.1 및 격리 `settings_test`에서 같은 Fixture로 실행했다. 워밍업 1회 뒤 계측 없는 5회 시간 중앙값을 기록하고 별도 렌더링에서 SQL을 셌다.

결정적 UUID로 비교한 전체 Payload SHA-256이 여섯 조건에서 일치했다. 비교에는 순서, 레이블, Action·Variant, 역할별 UUID·Scope, 채우기의 수량 버전이 포함된다. 두 측정 모두 표시 SQL 쓰기는 0회였다.

장전과 재장전은 같은 요청의 Source 후보와 장전 결과를 공유한다. Scope별 후보 재사용은 관찰 조건을 구분하며 역할별 정의·위치 필터를 다시 적용한다. 번호 행으로 검증된 ItemEntity를 표시용으로 재사용한다. 자동 재장전은 번호가 없는 탄창까지 포함하는 기존 도메인 후보 집합을 읽고 원래 우선순위를 사용한다. 상위 제공 검사, 표시 레이블과 Role 검증 등 관찰 조건이 다른 번호 조회와 후보 Snapshot 투영 비용은 남는다. 표시 요청의 캐시는 실행 Gateway로 전달되지 않는다.

## Issue #113 상점·소각 웹 Action Control

기준은 `e5eed12d9623c8cb9c704c6d62363badba536ef4`다. macOS arm64, Python 3.13.18, SQLite 3.53.1에서 기존 결과와 별도로 측정했다. 격리 `settings_test`에 공급상인, 소각기, 수량 1·2의 붕대 스택을 고정 UUID로 구성했다. 관찰 시각과 Manifest는 동일하다. 워밍업 1회 뒤 5회 시간 중앙값을 기록하고 별도 호출에서 SQL을 집계했다.

장비와 보관 표시는 기존 요청 캐시에서 Scope와 가시성을 검증한 ItemEntity를 재사용한다. 텍스트 기본 선택은 명령 한 번의 실물 맵과 종류별 배치 해석으로 기존 `sequence`, `pk`, 동률의 원래 순서 및 무효 참조의 실패 동작을 유지한다. 화면 캐시는 실행 Gateway에 전달되지 않는다.

21개 조건에서 전체 Payload 해시와 선택 UUID가 일치했고 표시 SQL 쓰기는 전후 0회였다. 텍스트 Fixture는 후보 10·100개에서 가장 작은 sequence의 영속 번호를 뒤로 이동시켰다. 공유 보관함의 기존 소유권 이전 트리 정책 SQL은 허용 후보 1 / 10 / 100개에서 각각 1 / 10 / 100회로 유지된다. 이는 중복 UUID 해석과 별개의 기존 정책 조회이며 공용 회수에도 적용된다. 운영 DB와 복수 서버 동시 쓰기는 실행하지 않았다. 기존 구버전 탭 수동 재현과 실제 OS 한글 IME의 검증 범위도 유지한다.
같은 UUID의 반복 단건 SELECT는 장비 14 / 23 / 113회, 텍스트 3 / 21 / 201회에서 각각 0회가 됐다. 공유 보관함의 후속 정책 SQL과 수량별 버튼 생성 비용은 남는다. 일부 소규모·회수 조건의 시간은 소폭 늘었으므로 시간 개선은 측정 조건별로 해석한다.

`tests.test_selection_exact`, `tests.test_storage_actions`, `tests.test_action_runtime`의 격리 회귀 67개와 실제 `때려 도움` 출력 회귀를 통과했다. 전체 Python 검사(`scripts/dev.py test --parallel 4`)에서 순수 294개와 통합 1,320개가 통과했다.
