# 첫 플레이 버전의 구조

## 개발 목표

사냥·장비 수집·성장을 우선하고 탐험·임무가 다음 사냥터를 연다.
주요 임무와 보스는 혼자 완료할 수 있다. 다중 접속과 같은 방의 채팅을 지원한다.

## 구현

- Python 3.13 / Evennia 6.1.0. 의존성은 uv.lock으로 고정한다.
- world/content.py: 방 8개, 일반 적 3종, 보스 1종, 아이템 8종.
- world/rules.py: 엔진과 독립된 전투·성장·보상 계산.
- typeclasses/explorers.py: 플레이어 상태를 한 Attribute에 저장하고 전투 타이머를 관리한다.
- commands/gameplay.py: 한국어 명령을 검증하고 같은 게임 규칙을 호출한다.
- server/conf/cmdparser.py: 활성 명령 집합과 접근 권한을 기준으로 `대상 + 행동`을 분리한다. 게임 명령은 이전 접두 문법으로 실행되지 않으며, 인증과 엔진 관리 명령은 기본 파서를 사용한다.
- world/bootstrap.py: 서버 시작 시 태그를 기준으로 월드를 생성한다. 재실행해도 방이나 출구가 중복되지 않는다.
- web: 빌드 과정이나 CDN 의존성이 없는 HTML/CSS/JavaScript 화면.
- WebSocket: Evennia의 v1.evennia.com 프로토콜을 사용한다. 브라우저는 명령과 인증 요청만 보내며 게임 결과는 서버가 계산한다.
- pz_state는 전체 화면 상태를 갱신하는 스냅샷이다. pz_auth는 전용 인증 입력·응답이다.

게임 입력은 마지막 공백 단위의 단어를 행동으로 해석하고 앞부분을 대상 인자로 전달한다. 단독 행동은 기존대로 사용한다.
채팅은 `'내용`을 우선 처리하고, 그 외에는 `내용 말` 또는 별칭 `내용 say`를 사용한다. 작은따옴표 이후의 마지막 단어는 행동으로 다시 해석하지 않는다.
웹 버튼도 같은 문법의 텍스트 명령을 서버로 전송한다. 입력 순서 변경은 저장 데이터의 ID와 형식을 바꾸지 않는다.

## 전투와 저장

교전 상대는 플레이어의 개인 상태에 존재한다. 같은 방에 여러 명이 있어도 처치 경쟁이나 임무 아이템 독점이 발생하지 않는다.
이 버전에는 파티 공동 전투를 아직 구현하지 않았다.

기본 공격은 서버 타이머가 2.5초마다 처리한다. 강타·방어·회복은 다음 차례 행동을 바꾸며, 반복 입력으로 시간을 진행할 수 없다.
강타는 3차례의 재사용 대기시간을 갖는다. 방어는 기본 공격을 유지하며 받는 피해를 줄이고, 회복은 공격을 대신한다.

전리품·경험치·적 제거를 같은 상태 스냅샷에 반영한다. 중복 타이머 생성을 막고 완료된 교전에 다시 보상을 지급하지 않는다.
이 보장은 단일 Evennia 게임 서버 프로세스에서의 동작을 전제로 한다. 여러 서버에서 동일 캐릭터를 동시에 갱신하는 구조는 지원하지 않는다.

정상 로그아웃 시 개인 교전 타이머를 취소하고 체력과 적 체력을 저장한다. 재접속 후 '공격'으로 재개한다.
비정상 연결 종료는 서버가 단절을 인지한 뒤 멈춘다. 오프라인 동안 추가 사냥 보상은 지급하지 않는다.
서버 재시작 후에도 교전 스냅샷을 유지하며, 타이머는 다시 '공격'할 때 만든다.

임무 플래그, 보급상자 획득 여부, 장비, 체력, 경험치, 크레딧, 방문 지역은 저장된다.
현재 버전은 같은 장비의 복수 개수를 보관하지만 강화·판매·거래는 제공하지 않는다.

## 운영 범위

기본 바인딩은 127.0.0.1이며 Telnet은 비활성화되어 있다. 현재는 로컬 개발용이다.
외부 테스트 전에는 HTTPS/WSS, 허용 호스트, 역방향 프록시, PostgreSQL, 백업과 복구 절차를 구성한다.
PostgreSQL 환경변수 연결점은 준비했지만 이 버전의 검증은 SQLite로 수행했다.
Docker Compose 운영 구성과 외부 배포는 후속 작업이다.
