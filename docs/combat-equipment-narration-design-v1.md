# 1. 문서의 목적과 효력

본 문서는 원시구역의 전투·장비 Narration 개선을 위한 최종 설계 계약이다. 기존 v1.5 기획안과 Design Freeze 리뷰에서 도출된 DF-01~DF-40 결정을 모두 통합한다.

**목적:** 구현자가 추가적인 제품 설계 결정을 내리지 않고도 기능을 구현하고 검증할 수 있도록 한다.

## 1.1 최종 목표
1. 무기와 적의 특징에 맞는 자연스러운 한국어 전투 메시지.
2. 공격·피격·HP 회복·정신력 회복·강화·약화를 의미별 부분 색상으로 구분.
3. 전체 문장이 아닌 핵심 텍스트만 강조.
4. 일반 공격과 전투 기술의 고유 의미 보존.
5. 실제 적용 피해와 출력 수치 일치.
6. 대련·보스·지원 행동·장비 행동의 일관된 표현.
7. 기존 게임 규칙과 영속 상태 불변.
8. Actor·Item 선언형 확장 유지.
9. 문장·의미 세그먼트 자동 검증.
10. 최소 변경으로 기존 테스트·CI·복구 계약 유지.

## 1.2 문서 간 우선순위
아키텍처 원칙과 도메인 불변식은 본 문서보다 우선한다. 본 문서는 Narration 전용 상세 계약이고 이전 v1.2~v1.5의 대응 항목을 대체한다. 명시되지 않은 기능·수신 정책·영속 구조 변경은 승인된 것으로 해석하지 않는다.

## 1.3 Freeze의 의미
사용자 출력, 문법, 피해·강도 의미, 문구 우선순위, 색상 역할, 정적 콘텐츠, 결과·전달 경계, PR 구분, 수용 테스트를 동결한다. 계약에 없는 재설계는 영향·대안·검증을 기록해 명시적 승인을 받는다. 내부 함수명·지역 변수는 의미 계약을 보존하면 구현자가 선택할 수 있다.

# 4. 한국어 출력 공통 계약

**문체:** 기존 서술형 평어(“베었다.”, “피해를 입혔다.”, “체력이 12 회복됐다.”, “보안고글을 썼다.”)를 유지한다. 기존 오류·명령 안내의 존댓말은 일괄 변경하지 않는다.

**플레이어 일반:** [무기][으로/로] [적][을/를] [동사][문장부호] [N] 피해를 입혔다.

**적 일반:** [적][이/가] [공격 수단][으로/로] 당신을 [동사][문장부호] [N] 피해를 입었다.

**적 특수:** [적][이/가] [prelude] 당신을 [특수 동사][문장부호] [N] 피해를 입었다.

**고정 템플릿 범위:**
- 무기 공격: 무기 + 도구 조사 + 대상 + 목적격 조사 + 동사
- 적 일반: 적 + 주격 조사 + instrument + 도구 조사 + 당신을 + 동사
- 적 특수: 적 + 주격 조사 + prelude + 당신을 + 동사
- 강타: 무기 + 도구 조사 + 적에게 + 강타를 가했다
- 사격 기술: 총기 + 도구 조사 + 적 + 목적격 조사 + 집중 사격했다
- 견제: 적 + 목적격 조사 + 견제했다
- 간파: 적 + 의 빈틈을 간파했다
- 지원·장비: 행동/슬롯별 고정 문장

범용 자연어 DSL, 자유형 템플릿 실행기, Callable 도입 금지. 일반 동사는 공통 목적격에 결합 가능한 완결형 타동사구만 허용한다. “적을 총탄을 발사했다”, “적을 방아쇠를 당겼다” 등의 이중 목적격·오류 문구 금지. 총기 일반형은 “쏘았다/사격했다” 사용.

조사는 기존 world/text.py의 particle()을 사용하고 실제 이름으로 계산한다. 장비 Action 결과에서는 사용자에게 표시되는 최종 선택 라벨로 조사를 계산한다. 기본 한 번의 공격은 하나의 Text 이벤트, 동작 뒤 공백 하나와 피해 결과를 사용하며 명시적 개행을 추가하지 않는다.

# 5. 피해량과 강도 결정

| 값 | 의미 |
|---|---|
| calculated_damage | 기존 Rules가 계산한 피해 |
| applied_damage | 해당 공격에서 HP 0 하한까지 실제 전투 체력이 감소한 양 |
| display_damage | 사용자에게 표시할 피해 = applied_damage |

일반적으로 applied_damage = min(calculated_damage, max(0, hp_before_attack)). 도메인이 이미 확정한 더 정확한 적용량이 있으면 해당 결과를 사용한다. 기존 HP 음수 계산 경로는 변경하지 않는다.

**플레이어→적:** 기존 receive_attack()의 Boss Scaling·피해 적용 순서를 유지하며 실제 차감한 HP를 사용. 남은 8 HP에 계산 피해 35면 표시 8.

**적→플레이어:** rules.enemy_attack()이 HP를 음수로 만들 수 있어도 공격 이전 체력으로 적용 피해를 확정하고, apply_defeat/응급 처치/구조 이후 상태로 역산하지 않는다. HP 6, 계산 피해 20이면 표시 피해 6.

**Duel:** state.actor_hp와 state.player_hp의 임시 자원을 사용하고, 일반 캐릭터 HP와 구분. 공격 방향별 자원 라벨을 달리하고 공통 공격 Narration을 사용한다.

**강도 판정:** 해당 공격 시점의 공식 target_max_hp(보스는 Scaling 후)를 사용, Narration에서 보스 HP 재계산 금지.
- Normal: 실제 피해 < 최대 HP 15% → 기본 동사와 마침표
- Heavy: 실제 피해 ≥ 최대 HP 15% → 강조 동사와 마침표
- Severe: 실제 피해 ≥ 최대 HP 30%이면서 ≥10 → 강조 동사와 느낌표

정수 곱셈으로 비교해 부동소수점 오차를 피한다. 피해 0이 유효한 공격에는 Normal을 사용하되, 존재하지 않는 회피/방어/치명타 연출을 만들지 않는다. 처치 여부로 강도 상향하지 않는다. 별도 처치 연출은 기존 적 사망 이벤트가 담당한다. 기술명만으로 느낌표 강제 금지.

# 6. 공격 표현 선택 우선순위

1. 오류·비공격 행동: 전용 템플릿
2. 적 특수 공격: Actor 특수 공격
3. 플레이어 기술: 기술 전용 템플릿
4. 일반 공격: 무기/Actor 정적 일반 공격
5. 적용 피해 기준 Normal/Heavy/Severe 동사와 문장부호

강타·사격·견제는 기술의 정체성을 보존하고 무기 일반 동사보다 우선. 총기 일반 “쏘았다” vs 사격 기술 “집중 사격했다” 구분하되 새로운 연속 발사·추가 비용 의미는 부여하지 않는다.

특수 공격 charged=True라도 자동 느낌표 금지; 강도에 따라 기본/강조/문장부호 결정. 여러 동사는 정적 선언 순서를 보존하고 기존 공격 회차 1부터 (round_index-1) % len(phrases)로 결정적 순환. 새 RNG·DB 카운터 금지. 지원 행동으로 후보가 건너뛰어도 허용. 동일 후보 중복 금지, 강·약 동사 동일 허용.

# 7. 정적 Narration 데이터 계약

ActorDefinition 최상위에 combat_narration: CombatNarrationSpec | None = None 추가. 기존 Actor 불변 구조와 호환되게 frozen dataclass/tuple을 사용한다.

    AttackPhrase(instrument: str, verb: str, strong_verb: str)
    SpecialAttackPhrase(prelude: str, verb: str, strong_verb: str)
    CombatNarrationSpec(normal_attacks: tuple[AttackPhrase,...],
                        special_attack: SpecialAttackPhrase|None = None,
                        telegraph: str|None = None)

전투 Capability Actor는 유효한 일반 공격 필수, 비전투 Actor는 필요 없음. special_period 있으면 특수 공격 및 예고 필수(최종 PR-B 전환 시 검증 활성). 문자열 빈 값/타입/중복 오류는 정적 검증에서 거절. 함수·전투 효과를 선언 데이터에 넣지 않는다.

특수 공격 Actor: 능선의우두머리, 밀림의포식자. 기존 기본 돌진/예고와 밀림 도약/덮치기 의미를 정적 콘텐츠로 이전. special_period는 Combat Profile 유지. special_verb/telegraph는 최종 Actor Narration 단일 SSOT로 이전한다.

Item Definition 최상위 combat_narration.normal은 (verb, strong_verb) 후보 tuple. equipment_properties.role == weapon인 모든 무기에 필수, 방패/offhand/방어구에는 불필요. 맨손은 공식 별도 콘텐츠. 장비 착용은 슬롯·역할 기본 동사를 사용하고 개별 예외는 필요할 때만 선언한다.

**잘못된 Fallback 금지:** 무기 미장착만 맨손, 잘못된 선언/알 수 없는 outcome/role은 명시 오류, 일반 장비는 합법적 슬롯 기본 동사.

# 9. 시맨틱 색상 정책

| 역할 | 의미 | 웹 색상 / 강조 범위 |
|---|---|---|
| combat_verb_outgoing | 공격 동사구·문장부호 | #EFB66D |
| damage_dealt | 입힌 피해 숫자+“피해” | #FFD098, 굵게 |

# 12. Narration Context 계약

새 전투 결과 엔진 금지. 확정 Domain Result를 바탕으로 비영속·불변 Context 구성. 논리 영역:
- Identity: 공격자/대상 정체성·표시 이름
- Action: 실제 수행한 action
- Equipment: 공격 당시 활성 무기 Snapshot
- Combat: 계산/적용 피해·대상 공식 최대 HP
- Effect: 최종 견제/간파 등의 결과
- Presentation: 공격 방향, 전투 모드, 기존 회차
- Outcome: 오류/지원/패배 구분

기술별로 사용하지 않는 필드를 억지로 채우지 않는다. 모든 결과를 재조회하거나 임의 추론하지 않는다. Context는 실행 행동/무기/피해/효과/자원/회차 확정 후 생성한다. 공격 직후 무기 교체가 이전 출력에 영향 주지 않아야 한다.

# 13. 회복 출력 경계

공통 표현 대상:
- presentation.support_result()
- skill_services.use_support()
- shared_combat.receive_attack() 동료 치료
- item_equipment_services.execute() 음식/음료
- shared_combat.enemy_tick() 패배 후 응급 처치
- 그 밖에 기존 명시적 회복 결과 메시지

회복 표현은 기존 Presentation의 작은 함수로 공유하고 새 Recovery Domain Service를 만들지 않는다. 예약에는 회복 성공색/확정 수치 없음. 실행 성공 시 실제 회복 수치만 강조, 오류는 기존 오류 의미. 자연 회복의 새 로그·HP Bar·상태창 재디자인 금지. 0 회복을 가짜 성공으로 표현하지 않는다.

# 15. 수신자·빈도·순서

공격자는 자신의 공격 결과, 피해자는 피격 결과, 실제 치료 수신자는 회복 알림, 보스 예고·사망·보상은 기존 참가자 정책을 따른다. 관전자 신규 방송 없음. 공격당 메시지 이벤트 추가 없음; 기존 하나의 공격 결과를 하나의 Text 이벤트로 표현. 사망/보상/구조는 독립 이벤트, 전달 순서·발생 시점 유지.

교전 시작 메시지의 반복 “기본 공격은 2.5초마다 이어진다”만 제거하고 기존 때려 도움말에는 주기 유지. 대련 최대 시간/행동 제한과 필수 경고 유지.

# 16. 오류·Rollback·Delivery 계약

- 정적 스키마/Role 구조 오류는 실행 전 검증.
- Narration은 DB/Evennia/웹 비의존 표현 계산; 게임 효과 재실행 금지.
- Commit **이전** Narration 생성 예외는 현재 world_change() 계약상 Rollback될 수 있음을 명시. 이 경우를 Commit 이후 전송 실패와 혼동 금지.
- Commit **이후** 메시지 전송 오류는 확정 피해/보상/자원 소비 재실행 금지. 기존 진단·격리 정책 유지.
- 새 영속 큐/Exactly-Once Delivery 보장 도입 금지.
- 실패 주입: 정적 실패, Commit 이전 생성 실패, Commit 이후 전송 실패, 중복 Tick, Duel 전달 실패, 동료 치료 전송 실패.

## 저장소 반영 상태

- Actor·무기·맨손 일반 공격 선언, 정적 검증, 문장 미리보기 스냅샷 및 장비 Action 출력을 구현했다. [PR-A (#98)](https://github.com/wonmin82/primal-zone/pull/98)은 리뷰 단계다. 장비 Action의 테스트는 번호가 붙은 최종 선택 라벨의 조사, 실제 반환 문자열과 의미 세그먼트를 확인한다.

- PR-B (#97)에서 공식 전투·회복·대련 출력 전환, 적용 피해량과 강도, 특수 공격 표현 이전 및 신규 의미색을 구현한다.
- 검증 실행과 리뷰 근거는 PR-A와 Issue #96에 기록한다.
