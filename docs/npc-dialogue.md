# NPC 키워드 대화와 개인 메시지

[Issue #47](https://github.com/wonmin82/primal-zone/issues/47)의 v3.5 FINAL 구현 계약이다. 사용자 조작은 [플레이 가이드](gameplay.md#npc-대화와-개인-메시지), 명령·별칭은 [어휘 기준](commands.md), 줄임말 이전은 [v13 정책](command-shortcuts.md#프로필-v13의-npc-대화-이전)을 따른다.

## 입력과 대상 선택

`말`·`say`와 작은따옴표는 기존 후치형 파서에서 동일한 Say 명령으로 연결한다. `윤대장에게 임무 말`과 `'윤대장에게 임무`는 동일 NPC와 Intent를 실행한다. 발화 1~300자, ANSI 제거·개행/제어문자 거절, 콤마·원문 보존 계약을 유지한다.

발화 앞부분의 `NPC선택자에게 본문`만 검사한다. 공통 `targets` 이름·별칭·정렬·번호를 재사용하되 `strict_single()`은 복수 DEFAULT 후보를 거절한다. 식별 가능한 주변 NPC가 없으면 `에게`를 포함한 전체 원문을 공개한다. 다른 방·감지 불가·플레이어/일반 객체 이름만 일치해도 이 정책을 따른다. 인식된 이름의 잘못된 번호·복수 후보·ALL은 발화 없이 오류다. 일반 문장 중간에 `에게`가 나온다는 이유만으로 상대를 선택하지 않는다.

대상을 선택해도 공개 발화는 대상 정보를 유지한다. 자동 선택은 명시적 상대 → 유효한 내 문맥 → 화제를 유일하게 지원하는 주변 NPC → 단일 NPC 인사 순이다. 여러 후보는 안내하고 일반 채팅에는 과도하게 끼어들지 않는다. NPC 응답을 다시 NPC 입력으로 처리하지 않는다.

## 선언형 Intent와 콘텐츠

`world/dialogue_intents.py`의 frozen Intent가 `intent_id`, `keyword`, `aliases`, `kind`, `priority`, `availability`, `handler`, `next_topics`, `mutates_state`를 소유한다. 표시·인식·웹 선택은 동일 SSOT를 참조한다. 정확한 키워드/등록 동의어를 우선하며 질문 패턴은 읽기 전용 화제에만 적용한다. 행동의 부분 문자열·부정형·의문형·가정형은 실행하지 않는다. 이해 실패 때 정확한 키워드를 안내하며 `네/아니요` 확인 계층이나 외부 AI는 없다.

### 기존 NPC 행동 전환표

| 기존 입력·출력·상태 변경 | 기존 접근 조건 | 새 입력과 서비스 경계 |
| --- | --- | --- |
| 윤대장 `대화`: 개인 임무 안내, 미시작이면 시작, 완료 조건이면 보고/보상, 출입증 재발급 | 같은 방·시야·비전투·임무 조건 | `윤대장에게 임무/진행/지역/출입증 말`은 조회만, `수락/보고/재발급 말`은 최종 검사 후 기존 issuer 서비스 |
| 길잡이 `대화`: 개인 밀림 안내 및 상태별 시작/보고/재발급 | 같은 방·시야·비전투·통신탑 완료 | `선발대 길잡이에게 임무/진행 말`과 명확한 `수락/보고/재발급 말`로 분리 |
| 교관·관리관 `대화`: 개인 역할/담당 서비스 설명, 성장 상태 변경 없음 | 같은 방·시야·안전 지역·비전투 | `교관이름에게 훈련 말`은 공개 안내, 실제 배워·배분·재분배는 기존 명령 |
| 상인 `대화`: 개인 상점 안내, 거래 없음 | 같은 방·시야·안전 지역·비전투 | `상인이름에게 보급 말`은 공개 안내, 실제 목록·사·가치·팔아는 기존 서비스 |
| 의무관·정산관: 기존 대화 Action 없음, 별도 서비스 | 같은 방·시야·안전 지역·비전투 | 의료·정산 화제는 공개 설명만, 회복·환율·교환은 기존 서비스 |

`ROOMS.hints`는 기존 `{text}`·`{target, action}` 외에 `{target, intent}`를 지원한다. 무결성 검사에서 대상·같은 방·NPC 유형·지원 Intent 및 SSOT 충돌을 확인한다. 실제 출력은 감지·view 조건을 적용한다. 상점 5곳의 서비스 행동은 정확히 `("목록", "사", "가치", "팔아")`다.

## 조회와 원자적 행동

`world/npc_dialogue.py`는 선택·문맥·조회·기존 서비스 호출·공개/개인 출력 경계를 소유한다. 조회는 프로필 사본과 콘텐츠만 읽으며 기존 가변 `commander_talk()`·`jungle_talk()`를 호출하지 않는다.

수락은 미시작 임무만, 보고는 시작·보스 처치·기존 완료 조건(통신탑 발전기 수리 포함)만 허용한다. 재발급은 완료·해당 출입증 부재 때만 허용한다. 기존 시야·위치·NPC available·비전투·안전·선행 임무 조건을 유지한다. `world_change()` 안에서 최종 조건을 다시 확인하고 `credential_service.issuer_talk()`/`reissue_credential()`과 기존 순수 규칙을 사용한다. 보상·아이템·경제 계산을 복제하지 않는다.

순서는 플레이어 발화 공개 → 보호 구간 최종 검사/변경/커밋 → `after_change()`의 성공 NPC 공개 발화 → 개인 지급 알림이다. 실패·rollback은 성공 대사와 지급 알림을 보내지 않는다. 기존 단일 서버 직렬화·원자 저장이 반복 보고와 중복 선택의 이중 지급을 막는다. 공개된 플레이어 발화 자체는 rollback하지 않는다.

## 공개 원문과 수신자별 출력

NPC 실제 대사 원문은 한 번 만들고 같은 방의 모든 Explorer에 동일하게 전달한다. 수신자마다 독립 Text 세그먼트를 생성한다. 활성 `〈화제〉`는 `dialogue_topic` 청록색, 활성 `〈행동〉`은 `dialogue_action` 황금색이며 비활성은 일반색·선택 없음이다. NPC 식별 불가 수신자도 발화를 들을 수 있지만 행동은 활성화하지 않는다.

플레이어와 NPC의 공개 발화는 모두 `Text(kind="chat")`의 `이름: 내용` 형식이다. 화자 이름만 각각 `player`·`npc` 역할이며 뒤의 `: `는 일반 `text`다. 플레이어 발화 원문과 NPC의 수신자별 키워드 역할을 유지한다. 입력 프롬프트에 남은 명령 기록과 서버가 전달한 자신의 공개 발화는 각각 표시하는 것이 정상이다. 두 행을 병합하거나 숨기지 않는다.

개인 활성 키워드 안내와 최초 사용법 안내는 `Text(kind="event")`인 시스템 출력이다. 안내 문구는 `muted`, 실제 입력 예시는 `command`, 명령 사이 ` · `는 일반 `text`를 사용한다. 빈 목록은 전체 `muted`이며 가짜 명령을 강조하지 않는다. 색상 제거 뒤의 문자열·안내 시점·반복 억제는 동일하다. 기존 `Explorer.msg()`가 웹의 `pz_log`/segments와 터미널의 `Text.ansi()`로 전달하며 새 UI·색상·메시지 프로토콜은 추가하지 않는다.

보상·아이템·칩 수량은 행동한 플레이어만 시스템 메시지로 받는다. 비색상 환경에도 수신자별 “현재 사용 가능” 입력을 별도로 안내한다. 이 개인 안내와 첫 사용 안내는 NPC 실제 대사에 섞지 않는다. 안내 목록은 대사에 우연히 등장한 단어가 아니라 `available_intents()`가 반환한 SSOT의 전체 활성 화제·행동(인사 제외)이다. 같은 NPC·같은 목록이면 추가 안내를 생략하며 NPC의 공개 대사는 항상 전달한다. 첫 안내·활성 목록 변경·명시적인 `화제 안내`/`사용 가능한 화제` 요청·필요한 이해 실패 안내 때 다시 출력한다. 요청은 기존 인사 Intent의 읽기 전용 별칭이며 새 행동을 추가하지 않는다.

개인 `ndb.npc_dialogue_guides`에는 NPC 영속 ID별 정규화된 키워드 목록·입력 대상 label·시각·위치만 보관한다. 동명 NPC 추가로 표시 번호가 바뀌면 유효한 입력을 다시 안내한다. 최대 32개이며 180초 만료, NPC가 방을 떠나거나 제거되면 다음 안내에서 정리한다. 이동·접속 해제·서버 종료 때 비우며 유효 문맥이 만료되거나 접근을 잃으면 해당 NPC 안내도 무효화한다. 듣는 플레이어의 안내 상태만 갱신하고 대화 문맥은 바꾸지 않는다. DB 필드·프로필 버전·마이그레이션은 추가하지 않는다.

문맥은 캐릭터 `ndb.npc_dialogue_context`의 NPC 영속 ID·Intent·활성 키워드·시각·위치·이해 실패 횟수다. 마지막 유효 대화 뒤 180초 동안 유지하며 이동·감지 상실·제거·명시적 상대 변경·만료·서버 재시작 때 무효다. 타인 대화 청취는 문맥을 갱신하지 않는다. `그다음은요`는 이전 Intent의 읽기 전용 후속 화제로 연결하며 행동을 자동 실행하지 않는다.

### 이해 실패와 화제 발견

명시적 NPC 지정에서 인식하지 못한 말에는 짧은 역할별 응답을 공개한다. 문맥 기반 자동 응답은 `그건`·`그것`·`그러면`·`이건`·`무슨 뜻` 등 지시어로 시작하고 `?` 또는 `나요`·`까요`·`가요`·`인지요`·`는지요`로 끝나는 후속 질문으로 한정한다. 예를 들어 `그건 어디서 찾나요?`에는 안내하지만 `오늘 저녁 뭐 먹나요?`에는 끼어들지 않는다. 등록된 정확한 키워드와 질문 패턴을 먼저 처리하고 다른 NPC의 명확한 화제 또는 복수 후보 안내가 이해 실패보다 우선한다. 미발견 `에게` 문장은 문맥으로 가로채지 않는다.

`available_dialogue_topics()`는 같은 활성 Intent 판정에서 인사와 상태 변경을 제외한 읽기 전용 화제 1~3개를 SSOT 순서로 반환한다. 응답의 꺾쇠 단어는 실제 등록 키워드뿐이며 실행 불가 행동을 권하지 않는다. 화제가 없으면 일반 텍스트로 안내한다. 같은 문맥의 첫 이해 실패만 공개 안내와 개인 입력 예시를 보내고, 연속 실패는 플레이어 발화만 공개한다. 명시적으로 NPC를 다시 지정한 질문에는 필요한 안내를 제공한다. 정상 대화·상대 변경·문맥 만료 뒤에는 실패 제한을 초기화한다. 실패는 마지막 유효 대화 시각·Intent를 갱신하거나 퀘스트·아이템·보상을 변경하지 않는다.

## 웹 선택과 접근성

서버가 불투명 토큰을 발급하고 수신 캐릭터 ID·원래 NPC 영속 ID·Intent ID·키워드·발급/만료 시각을 `ndb.npc_dialogue_tokens`에 바인딩한다. 유효 기간 180초, 캐릭터당 최대 256개이며 만료 정리·재시작/탈접속 무효화를 적용한다.

`pz_dialogue` 입력은 인증된 현재 캐릭터 제어 세션을 확인하고 공통 서비스 `select_keyword()`로 연결한다. 클라이언트는 토큰만 보내며 NPC를 이름/번호로 다시 선택하거나 임의 Intent를 믿지 않는다. 위치·감지·접근·비전투·현재 임무 조건을 재검증한다. 사라짐·변조·만료·다른 수신자/세션이면 fallback 없이 오류다. 성공한 상태 변경 토큰은 제거하고 조회 토큰은 현재 조건이 허용하면 재사용한다.

웹은 의미 세그먼트를 안전한 `textContent`로 렌더링하고 활성 키워드만 native button으로 만든다. Tab·Enter/Space, IME 조합 중 실행 방지, 포커스 outline·스크린리더의 화제/행동 설명을 제공한다. 청록색 `#8ce4df`·황금색 `#f2cd73`는 배경 `#101b17` 대비 4.5:1 이상이다. 자동 테스트는 렌더링·클릭/키보드·토큰 요청·비활성·HTML 문자·대비·서버 수신을 확인한다. 실제 브라우저·OS IME·시각 수동 검증은 #50에서 추가한다.

## 개인 메시지 저장과 프라이버시

`world/private_messaging.py`가 플레이어 대상 선택·온라인·차단·개인 전달·최근 상대를 관리한다. `대화`는 온라인인 다른 Explorer 한 명에게만 보내며 다른 방도 가능하다. `대답`은 최근 성공적으로 송수신한 상대 ID를 사용하고 실패/공개 대화는 이를 바꾸지 않는다. `대화거부`는 오프라인 캐릭터도 차단·해제하며 목록 상한은 100명이다.

영속 Attribute `private_messaging`에는 `version=1`, `last_private_peer_id`, `blocked_character_ids`만 저장한다. 메시지 본문·전체 이력·오프라인 보관함·읽음 상태는 저장하지 않는다. 두 상대의 최근 ID 저장과 차단 검사는 원자적으로 처리하며 커밋 뒤 개인 전송을 시도한다. 전송 성공은 서버 수락·전달 시도이며 네트워크 exactly-once나 열람 보장이 아니다. 주변/NPC로 방송하지 않고 차단 여부를 구체적으로 공개하지 않는다.

현재 Evennia 6.1 실제 AccountCmdSet의 `page`(Alias `tell`)와 CharacterCmdSet의 `whisper`를 확인하고 제거했다. 신규 공통 메시징 경로를 거치지 않는 사용자 개인 명령으로 차단을 우회할 수 없도록 CmdSet 테스트로 확인한다.

## 호환성과 검증 경계

프로필 v13은 방법 B를 사용한다. 공개 원문으로 바뀐 교관·상인과 상태별 임무 동작은 구형 의미와 동등하지 않아 자동 변환하지 않는다. 원본/이유·정의 전체 비활성·정적 간접 참조 전파·이름 충돌을 보존한다. 기존 장비·아이템·경제·성장·파티·전리품 authority와 런타임 순차 실행 제한은 유지한다.

개발 중 관련 경량 테스트, 최종 커밋 HEAD의 격리 Quick 성공 뒤 Push, 해당 HEAD의 원격 전체 CI 순서다. 실제 실행 결과는 [테스트 기록](playtest.md#issue-47-npc-대화개인-메시지-검증)을 따른다. #48의 일행 시스템은 구현하지 않으며 공개/개인 발화의 서비스 경계만 후속 연계를 제공한다. Cross-Issue·다중 세션 경합·장기 재시작·실 브라우저·OS IME·수동 종단 간 검증은 #50에서 추가한다.
