# 1. 설계 목적

원시구역의 방문 장소와 실제 이동 연결을 한 글자 노드와 연결선으로 표현하는 **범용 컬러 텍스트 탐사 지도**를 제공한다.

현재 지역의 평면도를 먼저 하드코딩하지 않는다. 새로운 Region과 Room이 대량으로 추가되어도 동일한 규칙으로 자동 생성하며, 복잡한 구조만 최소 선언형 보정으로 지원한다. 현재 67개 Room은 첫 번째 실콘텐츠 검증 세트이며 확장성의 최대치가 아니다.

우선순위: **기존 도메인의 불변식 → 서버 권위·공개 정책 → 실제 연결 정확성 → P-01~P-12 준수 → 선언형 확장 → 최소 충분 설계 → 처리·출력 비용 → UX·디자인**.

비목표: 자동 길찾기/이동, 지도 클릭 이동, 실제 지리 거리·축척, 원격 실시간 NPC/아이템/적/문 상태, 발견 이력 영속화, 별도 지도 DB·이동/관찰/권한 엔진, 범용 그래픽 레이아웃 프레임워크, 독립 SVG/Canvas 지도 엔진, 기존 Room/Exit ID나 플레이 데이터 변환.

# 2. 아키텍처 원칙·SSOT 및 불변식

최상위 규범은 기존 [아키텍처 원칙 P-01~P-12](https://github.com/wonmin82/primal-zone/blob/main/docs/architecture-principles.md)이며 본 문서는 그 지도 영역 구현 계약이다.

| 정보 | 권위 있는 원본 |
|---|---|
| Room 안정 ID/정적 내용 | 기존 `ROOMS` |
| Region·Room 소속 | `REGIONS`, `ROOM_REGION` |
| 방향·별칭·반대 방향 | 기존 `DIRECTIONS` |
| 실제 Exit 존재·목적지 | Evennia Exit |
| 탐사 방문 여부 | Explorer `visited` |
| 접근/관찰 공개 판단 | 기존 Access/Observation |
| 현재 문 상태 | 기존 Door 도메인 |
| Sheet·Connector 분류 | 선택적 지도 표현 메타데이터 |
| 좌표·경로 | 읽기 전용 파생 결과 |
| 의미별 문자·색상 | 기존 `world.text`·ANSI/웹 CSS |

**불변식:** (1) 좌표는 이동 권한·효과를 결정하지 않는다; (2) 없는 Exit을 지도에 생성하지 않는다; (3) Room을 복제하지 않는다; (4) 비공개 Room/Exit/ID를 전송하지 않는다; (5) 지도 자체는 게임 상태를 쓰지 않는다; (6) 기존 stable ID·방문 데이터 보존; (7) 올바른 게임 콘텐츠를 지도 표현 때문에 수정하도록 강제하지 않는다; (8) 부정확한 지도 대신 명시적 실패; (9) 신규 지역별 엔진 코드 분기 금지.

# 3. 범용 지도 모델

- **Region:** 기존 게임의 논리적 지역. 지도 때문에 의미·소속 계약을 변경하지 않는다.
- **Map Sheet:** 표현·조회 단위. 기본 Region당 1개를 자동 유도. 실제 층·구획·독립 탐색 공간을 분리할 이유가 있을 때만 다중 Sheet 선언. 실제 Room/Region 아님.
- **Sheet ID:** 기본은 Region ID에서 결정적 유도, 명시 Sheet는 고유 안정 ID. 이름·별칭·정렬·언어와 분리; ID 변경은 통제 대상.
- **Planar Room:** 방향 연결을 2D로 표시; 기본값.
- **Connector Room:** 계단참·승강기·포털·이동 허브처럼 출구 목록이 더 적절한 **표현 정책**. 별도 Typeclass가 아님. 특수 Exit을 가진 복도가 자동으로 Connector가 되지 않음.
- **완전 분류:** 정적 Room은 정확히 하나의 Planar Sheet 또는 Connector로 구분. Connector는 여러 Sheet와 연결 가능하되 실체 Room은 하나.

# 4. 최소 선언형 메타데이터

일반 Region에서는 **지도 전용 선언 0개**를 기본으로 한다. 기존 Region 등록·Room/Exit 정의만으로 기본 Sheet를 구성한다.

선택적 선언: 다층/구획의 Sheet, 특수 Room의 Connector, Sheet 이름·별칭, 기준 Room, 충돌 보정 Hint. Room의 Sheet/표현/Hint는 Room의 선택적 `map` 필드, Sheet 이름·별칭·기준은 Region의 Sheet 선언이 단일 소유. 별도 중복 Map Registry 금지.

예시(실제 코드 미반영):
~~~python
"map": {"sheet": "ruins_2f", "presentation": "planar"}
"map": {"presentation": "connector"}
~~~
허용 필드/타입을 검증하고 미확인 필드, 잘못된 참조, ID 중복을 거절. 새 Region 추가 시 기존 콘텐츠 집계 수정은 가능하지만 지도 엔진에 Region ID별 분기 추가 금지.

# 5. 서버 내부 그래프와 공개 데이터 경계

`기존 Room·실제 Exit → 서버 내부 신뢰 그래프 → 방문+기존 공개 정책 → 플레이어별 공개 그래프 → 배치·Semantic Text → ANSI/웹`.

서버 내부는 Room/Exit/목적지 안정 ID를 정합성·권한 판정에 사용할 수 있다. **이를 공개 DTO/렌더러에 그대로 전달하지 않는다.** 공개 그래프에는 공개된 노드·연결·경계만 둔다. 비공개 목적지의 실제 ID·좌표·연결은 제외한다. 공개 렌더링용 임시 키는 가능하나 최종 웹 응답에 내부 Room/Exit ID를 보내지 않는다.

기존 `exit_entries()`는 숨긴 목적지 ID를 반환하지 않는 공개 계약이므로 이 계약을 변경하지 않는다. 필요하면 기존 Access/Observation의 서버 내부 판정 책임을 재사용하되 **독립된 지도 권한 엔진을 복제하지 않는다**. 불확실한 권한은 허용으로 추측하지 않는다.

# 6. 방문·이름 공개·목적지 표시의 독립 판정

다섯 상태를 분리한다: (1) 출구 존재 공개 가능 (2) 목적지 방문 여부 (3) 목적지 식별/노드 표시 권한 (4) 목적지 Sheet (5) Planar 또는 특수 Exit.

| 출구 공개 | 방문 | 목적지 표시 권한 | 표시 |
|---|---|---|---|
| 아니요 | 무관 | 무관 | 비표시 |
| 예 | 아니요 | 아니요 | `?` |
| 예 | 아니요 | 예 | **여전히 `?`** |
| 예 | 예 | 아니요 | `?` |
| 예 | 예 | 예, 같은 Sheet | `o` (현재 Room이면 `@`) |
| 예 | 예 | 예, 다른 Sheet | `+` |

`@`=실제 현재 위치, `o`=방문하고 공개 가능한 Room, `?`=출구는 공개되었으나 **목적지 노드를 표시할 수 없는 경계**(미방문 또는 식별 권한 제한), `+`=다른 Sheet의 방문·식별 가능한 목적지. 이름을 원격 관찰로 알고 있어도 `visited`에 없다면 `o` 아님. 현재 Room의 표시를 위해 `visited`를 쓰거나 보정하지 않는다. 전체 미탐사 Room 수 비공개.

# 7. 방문한 원격 Room의 정적 공개

공식 정책은 **조회 시점의 공개 가능한 정적 이동 구조**, 과거 방문 시점의 재연이 아니다. 원격 Room의 현재 Door/전투/시야/신규 동적 Exit이나 실시간 상태를 새로 관찰하지 않는다. 원격 지도 생성을 위해 `context_for()` 같은 실시간 관찰 경로를 Room마다 반복 호출하지 않는다. 실제 정적 Exit과 콘텐츠 선언의 일치를 확인하고 기존 출구의 `view` 등 접근 정책을 읽기 전용으로 반영한다. 판정을 안전하게 수행할 수 없다면 공개하지 않는다.

`visited`에는 과거 출구 발견 이력이 없으므로 과거 방문 후 추가된 **정적 Exit**도 현재 공개 정책이 허용하면 나타날 수 있음(의도된 방문 기반 탐사 정책). 방문 기록은 유지하지만 현재 권한이 필요한 정보는 권한 정책 우선.

# 8. 신규 문자 지도와 기존 목록의 호환성

- `지도`: 신규 문자 지도. 원격 동적 Exit을 정적 평면 구조에 추가하지 않음.
- `지도 근처`: 현재 Room에서 공개 가능한 동적 Exit은 별도 안내 가능.
- `지도 전체`: 동적 Exit만으로 미방문 Sheet를 새로 공개하지 않음.
- **`지도 목록`: 기존 `지도`의 방문 목록/Region 그룹/실제 Exit/방향 정렬/미탐사/정적 폐쇄/특수 출구/원격 동적 Exit 의미까지 보존**.
- `출구`: 기존 실시간 출력 유지.
- 지도 생성 실패 시 **`지도 목록`을 자동 호출하거나 출력하지 않고**, `지도 목록` 실행만 안내. 성공/실패에 따라 신규 지도 정보 공개 범위가 변해서는 안 됨.
- 기존 `test_directions.py`의 방향·원격 동적 Exit 등 의미는 `지도 목록`으로 이전해 회귀 검증(보호 의미 삭제 금지). 기본 출력 변경, 도움말 변경, 명령 인자 추가는 공개 계약 변경으로 기록.

# 9. 결정적 자동 배치

공개된 방향 그래프만 사용. 기존 `DIRECTIONS`에서 방향 벡터를 유도한다.

| 방향 | dx | dy |
|---|---:|---:|
| 북 | 0 | -1 |
| 북동 | 1 | -1 |
| 동 | 1 | 0 |
| 남동 | 1 | 1 |
| 남 | 0 | 1 |
| 남서 | -1 | 1 |
| 서 | -1 | 0 |
| 북서 | -1 | -1 |

논리 좌표이지 실제 거리/지도 축척 아님. 공개 그래프 연결 성분마다 기준 Room을 선택: (1) 공개된 명시적 기준 (2) 공개된 Region 진입 Room (3) 공개 Room ID 결정 정렬. 비공개 기준을 이용하지 않음.

처리 순서: 공개 그래프 → 연결 성분 → 결정적 기준 → 유효 공개 Hint → 기본 방향 좌표 → Hint 제약 → 경로·방향 검사 → 중복·교차·가짜 접속점 검사 → 문자 격자. BFS 또는 동등한 내부 구현 가능. DB 순서·실행 순서에 좌우되지 않음.

순환/다중 경로는 실제 Room당 노드 하나. 비연결 성분의 상대 위치를 추측하지 않고, 비공개 Room 경유 연결을 생성하지 않음. 동일 공개 그래프·메타데이터·옵션이면 동일 결과. 탐사 확장에 따라 화면 배치가 재정렬될 수 있으나 불필요한 재배치를 최소화한다. 비공개 데이터를 쓰거나 좌표를 새로 영속화해 절대 안정성을 보장하지 않음.

# 10. Layout Hint — 검증 가능한 제한적 선언

기본 자동 배치가 어려운 **정상 게임 구조**를 위한 최소 보정이며, 실제 Room/Exit/권한/방향을 변경하지 않는다.

**허용:**
1. `Room Position Hint`: 공개된 **같은 Sheet의 실제 정적 방향 Exit로 인접한** 기준 Room에 대한 상대 정수 오프셋. `relative_to`는 실제 안정 Room ID, `offset: [dx,dy]`; `[0,0]` 금지; Room당 최대 하나; Hint 참조 사이클 금지. 공개 그래프에 기준 Room이 없으면 해당 Hint 미적용.
2. `Exit Route Hint`: 출발 Room의 실제 정적 방향 Exit 이름을 키로, 출발 Room을 원점으로 하는 정수 격자 `via` 경유점 순서. 모든 경유점과 연결 선분은 결정적·유효. 0길이·반복 경유점·자기 교차 금지.

예시(설명용):
~~~python
"map": {"layout": {"position": {"relative_to": "hall", "offset": [3, 0]}}}
"map": {"layout": {"routes": {"동": {"via": [[1, 0], [2, 0], [2, 1]]}}}}
~~~

양방향 정적 Exit은 한 개의 논리적 통로이며 안정 ID 정렬로 정한 한쪽만 Route Hint 선언; 반대편은 경로 역순. 동일 통로의 모순된 양방향 독립 Hint 금지.

**우선순위:** 실제 Exit·공개 정책 > 유효 Position Hint > 유효 Route Hint > 자동 배치. 최초 선분과 목적지 진입 방향은 실제 Exit 방향과 일치해야 한다. 다른 Room 관통·가짜 연결점·다른 비연결 통로 교차·Room 복제·미공개 구조 누출 금지.

**공개 안전:** 전체 월드 좌표를 배치한 후 비공개 Room만 숨기지 않는다. 공개 그래프를 먼저 결정하고 양쪽 노드·Exit 등이 공개된 Hint만 적용한다. 비공개 목적지의 Route Hint는 사용하지 않고 출발 방향 경계 기호만 생성. 공개 연결에 불필요한 공간은 정규화한다. 동일 공개 그래프·적용 가능한 Hint인 두 입력은 비공개 월드 차이가 있어도 출력 동일해야 함.

잘못된 참조·필드·타입·순환·중복·충돌·방향/보안 위반은 정적 선언 오류. 정상 그래프를 모든 유효 Hint로도 정확히 표현할 수 없으면 **표현 불가**, 콘텐츠 오류 아님. 새 범용 그래프 DSL·제약 해결기를 도입하지 않음.

# 11. 기호·연결선·상태

| 표시 | 의미 |
|---|---|
| `@` | 실제 현재 Room |
| `o` | 방문 + 공개 가능 |
| `?` | 목적지 노드를 표시할 수 없는 공개 출구의 경계 |
| `+` | 다른 Sheet의 방문·공개 가능한 목적지 경계 |
| `×` | 정적 `blocked_exits` 또는 현재 Room에서 확인한 Door 차단 |
| `─ │ ╱ ╲` | 실제 공개 Exit의 연결선 |
| `…` | 현재 뷰포트에서 잘린 공개 연결 |

비공개 Exit은 비표시. 비공개 목적지의 실제 좌표·추가 출구 사용 금지. `?`가 기존 공개 노드와 충돌하면 안전한 위치/별도 텍스트 안내, 불가하면 명시적 실패. 교차·접속점이 실제 이동을 암시하지 않아야 함.

`blocked_exits`는 실제 목적지가 없는 정적 폐쇄 방향이므로 가상의 Room 생성 금지. 닫힘·잠김 Door는 **현재 Room의 공개 가능한 상태에만** `×` 오버레이; 원격 실시간 상태 금지. 출입증·임무·전투 등 현재 이동 제한은 구조선 자체를 삭제하지 않고 상세 사유는 `출구` 담당. 현재 정적 방향 Exit의 역방향 무결성 계약 유지. 미래 단방향은 도메인 승인 후 별도 반영.

# 12. Connector

계단참·승강기·포털 등의 실제 Room을 고유 ID 하나로 유지, Planar Sheet에 중복 복제 금지. 현재 Connector에서 `지도` 실행 시 공개 가능한 실제 출구 목록 제공(예: `[지도] 본부 승강기`, `1층 · 2층 · 3층 / 4층 · 5층 · 옥상`). 일반 Planar Room의 특수 Exit은 지도 아래 `계단 · 승강기`처럼 별도 안내. Connector도 실제 Room이므로 `visited`를 활용하지만 Planar 노드 수로 중복 집계하지 않음.

# 13. 대형 지도·뷰포트

- `지도` 본문 **60 표시 셀 × 24행** 기본 상한. ANSI 코드는 폭 제외. 고정폭 문자 셀 기준, 한글 장소명은 격자 본문 밖.
- 들어오면 전체 공개 Sheet, 넘으면 실제 현재 Room 또는 지정 방문 Room 중심 부분 지도와 부분 표시 안내.
- 화면 밖에 잘린 **공개 연결**은 `…`; 미탐사 `?`, 타 Sheet `+`, 차단 `×`와 의미 구분. 비공개 출구는 아무것도 그리지 않음.
- `지도 근처`: 한 단계 공개 출구. 매우 많은 출구의 허브에서 한도 초과 시 결정적 순서로 범위 제한하고 생략 사실 안내. 목적지·방향 임의 왜곡 금지.
- ASCII 모드: `-`, `|`, `/`, `\\`, `@`, `o`, `?`, `+`, `x`, `...`. Unicode와 같은 공개 구조·방향·의미.
- 출력하지 않는 거대한 빈 격자 전체를 무조건 생성하지 않는다. 공개 그래프 계산과 실제 출력 셀 비용을 분리.

# 14. 명령·이름 선택 계약

| 명령 | 역할 |
|---|---|
| `지도` / `지` | 현재 Sheet 또는 Connector |
| `지도 근처` | 현재 Room 한 단계 |
| `지도 전체` | 방문한 Region/Sheet 개요 |
| `지도 목록` | 기존 방문 Room/Exit 목록 |
| `지도 <지도명>` | 공개 가능한 특정 Sheet |
| `지도 중심 <방문 장소>` | 방문 장소 중심 뷰포트 |
| `지도 ascii` | 현재 지도 ASCII |
| `지도 도움말` | 기호·사용법 |

예약 인자(근처/전체/목록/중심/ascii/도움말)와 Sheet 별칭 충돌은 정적 검증 오류. 동명이인·다중 후보는 임의 first-wins 금지. Sheet 이름+장소 이름으로 한정하고, 같은 Sheet 내부 중복이면 공개 가능한 지도 조회 별칭을 고유 선언. 새로운 영속 B-1 번호 도입 금지. 비공개 후보의 식별자·존재를 오류로 유출하지 않음. 다른 Sheet를 볼 때 실제 현재 위치가 없으면 `@` 없음. 잘못된 조회를 다른 Room/Sheet로 자동 대체하지 않음.

# 15. 정적 검증 vs 런타임 검증

**정적 콘텐츠 검증:** Room/Region/Sheet 참조, 안정 ID/별칭 충돌, Planar/Connector 분류, 방향/역방향, 정적 Exit 정의, Hint 필드·타입·참조·순환·경로, 겹침·가짜 접속점, Sheet 경계. 기존 `content/integrity.py`와 규칙 중복 금지.

**런타임 요청:** 해당 범위의 실제 Exit 존재/목적지, 기존 접근·관찰 공개, 방문, 현재 위치, 관련 정적-실물 정합성만 검사. 매 명령마다 월드 전체 무결성 재검증 금지. 전체 정적 그래프에서 만든 좌표를 그대로 공개 지도에 쓰지 않는다. 유효 월드지만 평면 문자 표현이 안 되는 경우는 도메인 콘텐츠 오류와 구별.

# 16. 오류와 안전한 실패

| 분류 | 상황 | 공식 동작 |
|---|---|---|
| `LayoutUnrepresentable` | 유효 그래프의 문자 표현 불가 | 명시적 실패 안내 |
| `MapDeclarationInvalid` | 잘못된 map/Hint | 정적 검증 실패 |
| `RuntimeGraphMismatch` | 실제 Exit ≠ 정적 계약 | 운영 진단 + 안전한 안내 |
| `MapAccessDenied` | 미공개·권한 없는 지도 | 존재 추론 불가능한 거절 |
| `ProjectionError` | 공개 Projection 계산 실패 | 진단 + 안전한 실패 |
| `DynamicExitUnplaced` | 동적 Exit의 평면 미배치 | 정상 예외, 오류 아님 |

실패 메시지 예:\
> 지도를 정확하게 표시할 수 없습니다.\
> 방문 장소는 '지도 목록'으로 확인하세요.

**`지도 목록` 자동 실행 금지.** 서버 내부 로그에는 ID/오류 유형 포함, 클라이언트에는 비공개 ID 없음. 데이터 손상 시에도 사용자 DB 자동 초기화·변환·삭제 금지. 정상 동적·비방향 Exit은 `출구` 등 공식 조회에서 공개 정책대로 표시.

# 17. 명령 읽기 전용 생명주기

지도 자체의 Projection·렌더링은 방문·프로필·Room·Exit·Door·Quest·Combat·Inventory 등 영속 도메인 상태를 쓰지 않는다. 현재 `GameCommand.func()`는 일반 명령 후 전체 Explorer `push_state`를 예약하므로 `read_only=True`만으로 해결되지 않음. `Exits`와 유사한 명시적 조회 실행 경로를 사용하고 전체 접속자 불필요 갱신 금지. 기존 Output/Prompt/Recovery 정합화 생명주기는 무단으로 차단하지 않는다. 테스트는 (1) **지도 자체 쓰기 0** (2) 정당한 Recovery 정합화 보존 (3) 추가 전체 push 없음 을 구분한다.

# 18. 성능

정적 구조를 필요에 따라 메모리 재사용하고, 플레이어별 공개 Projection은 요청 시 계산. 개인별 영속 지도 캐시·복잡한 무효화 금지. 대상 Sheet/근처 범위만 조회, 가능한 묶음 조회, Room별 N+1 호출·매 요청 전체 정적 검사 금지. 렌더링은 60×24 뷰포트에 맞춰 불필요한 빈 문자 격자 생성 금지.

10/100/1,000 Room 합성 그래프로 그래프·배치·렌더링 시간, DB 호출 수, 메모리, 출력 셀·전송 크기·동시 요청 비용을 측정. 수치적 성능 허용은 실제 환경 측정과 PR Gate에서 평가. 미실행 측정 PASS 금지.

# 19. 터미널·웹 디자인

**기본:** 현재 `@`, 방문 `o`, 미표시 경계 `?`, 타 Sheet `+`, 차단 `×`, 선문자, 범위 `…`. 지도 본문에 한글 Room 이름 반복 금지, 상단에 현재 장소명 한 번. 긴 범례 매번 출력하지 않음. ANSI 없이도 기호로 의미 이해.

| 현재 | `#BCE88F` |
| 방문 | `#E1E9DF` |
| 목적지 미표시 | `#94A59B` |

기존 `world.text` 의미별 텍스트 역할 우선 재사용, 꼭 필요할 때만 지도 전용 역할 최소 추가. 웹은 서버 공개 문자 지도 결과만 사용; JS에서 그래프/권한 재계산 금지. 고정폭·지도 전용 nowrap·수평 스크롤, 일반 `.log-entry` 줄바꿈 유지. 색만으로 구분 금지, 스크린리더용 구조 요약 제공. 기존 이동 버튼 보존, 지도 클릭 이동 없음.

# 20. 현재 월드 검증

현행 정적 콘텐츠 **67 Room**(본부 52, 전초구역 8, 깊은 밀림 7). 예상 표시:

| 표현 단위 | Room |
|---|---:|
| 전초구역 | 8 |
| 깊은 밀림 | 7 |
| 본부 1F/2F/3F | 4 / 6 / 6 |
| 본부 4F/5F/옥상 | 9 / 11 / 9 |
| 계단 Connector | 6 |
| 공용 승강기 Connector | 1 |
| 합계 | **67** |

이는 **미실행 예상 분류**이며 PASS 아님. 정적 직선·분기·순환·8방향·복도·폐쇄·Region/Sheet 경계·계단·공용 승강기·접근 제한을 지역 전용 엔진 분기 없이 검증한다. 현재 월드 성공은 미래 대규모 콘텐츠 전체 검증의 대체가 아님.

# 21. 합성·권한·회귀 검증

신규 Region을 생성해 지도 엔진 코드 변경 없이 처리하는 테스트. 10/100/1,000 Room, 직선/분기/순환/비연결/다층/공용 Connector/Position Hint/Route Hint/정상 표현 불가/잘못된 Hint/런타임 Exit 불일치 테스트.

**공개 매트릭스:** 미방문·이름만 관찰 가능(`?` 유지), 방문/공개(`o`), 방문/미공개(`?`), 다른 Sheet 방문/공개(`+`), 출구 비공개(비표시), 방문 이후 새 정적 Exit(현재 공개 정책), 원격 동적 Exit(신규 평면 지도 제외), 기존 `지도 목록`의 원격 동적 Exit(보존).

비공개 월드 구조만 달리한 두 입력에서 동일한 공개 그래프·공개 Hint라면 **공개 텍스트/웹 페이로드 동일성** 검증. 중복 이름·예약어·중심 이동·부분 뷰포트·Unicode/ASCII·ANSI 제거·Read-only·Recovery·프롬프트·기존 테스트 의미 검증.

# 24. Design Freeze 및 리뷰 종료 기준

**설계 리뷰 종료:** D01~D40 의미 충돌 없음, 기호 공개 의미 명확, 내부 ID→공개 DTO 경계, 기존 목록과 신규 지도 구분, Hint 입력·결과·실패 검증 가능, 표현 불가와 손상된 데이터 구별, 대형 지도 한도, 새 Region 하드코딩 0, 기존 게임 데이터 불변, 검증 가능한 완료 조건.

**실제 구현 이후에만 검증:** 67 Room 자동 배치, Hint 충돌 해결, 실제 Exit 런타임, 공개/보안 통합, ANSI·ASCII 셀 폭, 웹 브라우저, 성능, 재시작/DB 유지, CI. **NOT RUN ≠ PASS.**

**변경 통제:** 공개 정보, 방문/식별 기호, Exit·실제 이동, Hint 스키마, Sheet/Connector 소유권, 기본 지도 명령·목록 호환, 오류 정책, stable ID/영속, 읽기 전용은 Epic에 영향 분석·승인 후 변경. 내부 동등 알고리즘·함수 구분·측정 최적화는 계약 준수 시 구현자 판단.

# 25. 결론

원시구역 지도는 **기존 월드의 공개 가능한 이동 구조를 범용적으로 보여주는 읽기 전용 Projection**이다. 기존 Room/Exit/visited가 SSOT, 일반 Region은 자동 배치, 필요한 경우에만 상대 Hint, 공개되지 않은 월드 정보는 배치·출력에 사용하지 않음, 기존 목록 의미 보존, 명시적 실패, 대규모 뷰포트, 데이터 변경·과도한 새 프레임워크 금지. 현재 월드와 신규 합성 콘텐츠의 실제 증거로 완료를 판단한다.
