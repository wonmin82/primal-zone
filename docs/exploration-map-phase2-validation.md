# 탐사 지도 Phase 2 검증 기록

[설계 v2.2 FINAL](exploration-map-design-v2.2.md)과 [Phase 1 기록](exploration-map-phase1-validation.md)을 이어받는다. 작업 기준은 Phase 1이 병합된 `68eff4b6abe4ad1658933d9c074a7a324d04c43e`이고, 해당 SHA의 [main CI](https://github.com/wonmin82/primal-zone/actions/runs/44898909554) 네 검사가 성공했다.

## 동작과 경계

- 주변 행동의 접기 가능한 지도에 서버의 Semantic Text를 표시한다. 현재 Sheet 또는 Connector 보기, 공개 Sheet 선택, 방문 장소 이름이나 별칭으로 중심 지정, 현재 위치 복귀와 새로고침을 제공한다. 방향 버튼과 게임 명령이 이동을 담당한다.
- 기존 `require_session()`을 전송 전후에 사용한다. `pz_map` 요청은 증가하는 정수 `id`와 선택적인 공개 이름 `sheet`, `center`만 받는다. 응답은 해당 세션에만 반환한다. 제목·공개 조각·뷰포트의 중심 후보·공개 Sheet 이름·상태·접근성 요약을 포함한다. 내부 ID·좌표·Hint·그래프는 보내지 않는다.
- 기존 상태에는 세션 소유자와 revision의 불투명 토큰을 붙인다. 위치, 방문, 현재의 공개 출구와 관찰한 문 차단이 달라지면 revision을 바꾼다. 열린 지도에서 실제 조회에 사용된 `view` 판정을 현재 상태 전송과 1초 간격 사이에 다시 확인한다. 공격·HP·정신력으로만 상태가 변하면 공개 지도를 다시 계산하지 않는다. 권한이 바뀌면 기존 표시부터 제거한다. 별도 상태 전송이 없으면 권한 변경 감지는 최대 1초와 서버 스케줄링 지연의 영향을 받는다.
- 지도를 닫거나 제어권을 잃으면 해당 세션의 확인 작업을 정리한다. 최신 요청 하나만 지연 실행하며, 브라우저는 현재 소켓·소유자·revision·요청 ID를 모두 확인한다. 지도 요청은 쓰기, 프롬프트, 전체 접속자 상태 갱신을 발생시키지 않는다.
- 접근성 요약에는 현재 위치와 화면에 보이는 공개 노드·연결을 사용한다. 격자는 접근성 트리에서 문자 나열을 숨기고, 요약과 텍스트 기호 설명을 제공한다. 좁은 화면에서 지도 영역 내부를 스크롤하며 일반 게임 로그의 기존 줄바꿈을 유지한다.

## 재현과 증거

macOS 27.2.1 arm64, Python 3.13.18, Evennia 6.1.0, SQLite 3.53.1, Chromium 156.0.8078.4. 정확한 제출 SHA와 원격 CI는 PR Validation에서 확인한다.

- `.venv/bin/python scripts/dev.py check`, `node --check game/web/static/webclient/js/primal.js`, `npm run test:contracts`의 직접 검사를 실행했다. JS 계약 62개가 통과했다.
- `.venv/bin/python scripts/dev.py test tests.test_minimap tests.test_doors tests.test_exploration_map --parallel 1` 통합 77개가 통과했다. 실제 67개 Room에서 터미널과 웹의 의미별 조각 동등성을 비교했다. 공개 대상 이외 입력, 세션 제어권 상실, 숨긴 구조 변경의 페이로드 동일성, 쓰기 0, 최신 요청 수렴, 권한 무효화도 확인했다.
- 실제 Chromium의 `TEST-104-01`, `TEST-104-02`와 격리 통합 `TEST-E2E-02`에서 방문 기록이 다른 A/B, 재접속, 기존 이동 버튼과 명령, 본부 층·옥상·계단·승강기, 전초구역·깊은 밀림, 넓고 좁은 화면과 확대·글꼴 폴백을 확인했다. 자동 접근성 검증은 접근성 트리와 키보드 조작 범위이며 실제 보조기기 소리 출력은 측정하지 않았다.
- 임의 응답 역전·캐릭터 전환은 JavaScript 메시지 경계의 자동 검사에 포함했다. 이번 실제 OS 한글 IME 수동 실행은 NOT RUN이며 기존 사용자 확인은 [과거 기록](actor-phase2-validation.md)을 재사용했다. 중심 입력의 조합 중 Enter 억제는 자동 검증했다.

## 성능

격리 DB에서 `.venv/bin/python scripts/dev.py test tests.bench_minimap.WebMapBenchmark.test_benchmark_map_transport --parallel 1` 실행. 요청→공개 응답의 웜 20회 중앙값/P95, 별도 SQL 횟수·Python 피크, 실제 WebSocket JSON 형식의 크기다. 합성 케이스는 Phase 1 직선 fixture의 실제 Room/Exit ORM을 쓰며 조회자 현재 위치와 방문 목록은 fixture로 주입한다. Chromium DOM은 같은 JSON을 실제 UI에 넣고 30회 DOM 교체 및 레이아웃 읽기를 계측했다. WebSocket 왕복과 브라우저 페인트 전체는 DOM 계측 범위 밖이다.

| 시나리오 | 서버 중앙값/P95 ms | SQL | Python 피크 B | JSON B | Chromium DOM 중앙값/P95 ms |
|---|---:|---:|---:|---:|---:|
| 실제 본부 5층 11 Room | 4.506 / 4.766 | 21 | 144,890 | 3,749 | 0.2 / 0.6 |
| 합성 10 | 1.792 / 1.972 | 8 | 63,488 | 1,838 | 0.1 / 0.2 |
| 합성 100 | 4.627 / 4.726 | 8 | 186,987 | 3,890 | 0.2 / 0.3 |
| 합성 1,000 | 34.059 / 56.257 | 8 | 2,344,308 | 3,929 | 0.2 / 0.3 |

100·1,000 Room에서 375px 창의 동일 505px 문자 내용을 315px 지도 영역 안에서 스크롤했다. 네트워크에는 잘린 뷰포트와 관련 공개 텍스트가 전달된다. 실제 A/B 검증에서는 이동 외 상태 전송을 받은 뒤 추가 지도 요청이 각각 0건이었다. 서버 집중 테스트에서도 동일 신호의 상태 전송 8회에 Projection이 재실행되지 않았다. 대형 Sheet의 권한 재확인 비용은 노드·출구 수에 따라 증가하며 실제 운영 동시 접속 부하는 미측정이다. 별도 캐시나 Bounded Projection은 적용하지 않았다.

## Gate

V1은 현재 월드의 실제 서버와 브라우저 대표 경로, 공개 결과 동등성과 격리·오류 테스트를 근거로 판단한다. V2는 Chromium과 자동 접근성의 확인 범위를 적용한다. V3는 서버·DOM 계측, 상태·영속성 회귀 및 새 CI를 구별한다. PR 제출 단계에서는 사용자 승인 병합, 병합 후 main CI, Issue 및 Epic Closeout이 미완료다.

### 제출 후보의 추가 근거

- 임시로 만든 격리 관리자 fixture를 각 Room에 배치한 실제 Chromium `TEST-104-WORLD`에서 평면 60개의 `@`·60×24 제한과 Connector 7개의 목록을 확인했다. 별도 일반 플레이어 경로에서는 공식 이동과 공개 권한을 검증했다. 따라서 관리자 fixture는 실제 플레이 이동 권한의 검증을 대체하지 않는다.
- 최종 UI의 일반 플레이어 Chromium 집중 검사에서 A/B의 명시적 갱신 2건을 겹쳐 실행했다. Playwright 클릭과 응답 대기를 포함한 벽시계 시간은 144.849ms였다. 한 세션의 실제 응답 표본 5건은 928~2,034B, 요청부터 DOM 반영까지 7.1~49.6ms, DOM 교체 0.1~0.5ms였다.
- 로컬 전체 테스트의 선행 실행은 기존 Semantic 역할 검사가 이동된 공용 allowlist 변수명을 찾지 못해 실패 1건을 냈다. 역할 집합과 색상 비교는 그대로 유지하고 참조 이름을 고쳐 해당 테스트를 재검증했다. 최종 전체 검사는 PR CI의 결과를 사용한다.
- 독립 감사에서 빠른 최신 갱신이 제한 시간 안에서 수동 오류로 끝나는 경로를 발견했다. 최신 요청 하나를 지연 실행하고 revision이 바뀌면 대기 중인 이전 요청을 취소하도록 수정했다. 독립 리뷰에서 확인한 중심 지정 후 Sheet 선택 표시도 보완했다.
