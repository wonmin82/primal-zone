# 문·잠금·관리실 열쇠

[Issue #49 v1.3 FREEZE](https://github.com/wonmin82/primal-zone/issues/49)의 D01~D14, VIEW-01~VIEW-09가 설계 기준이다. 이 문서는 현재 구현과 운영 경계를 설명하며 원래 설계 전문과 당시 NOT RUN 기록은 Issue에 보존한다. 자동 검증 근거는 [RT/CV 추적표](issue49-requirement-tests.md), 실제 실행과 실패 이력은 [테스트 기록](playtest.md#issue-49-문과-열쇠-검증)을 따른다.

## 플레이 방법

본부 중앙 로비의 동쪽 관리실 문은 처음 잠겨 있다. 휴게실의 `관리실 열쇠함 조사`로 관리실 열쇠를 무료 발급받는다. 캐릭터별 정상 소유 열쇠는 하나이며 실제 소실 후에는 무료 재발급된다. 손상된 소유권이나 중복 데이터는 새 열쇠로 덮어쓰지 않고 관리자 확인을 요청한다. 열쇠는 `가진거`·`정보`에서 확인하며 양도·버리기·보관·판매·소각·소비·장착·장전·전리품 이동을 허용하지 않는다. 출입증이나 임무 Gate를 대신하지 않는다.

```text
관리실 열쇠함 조사
관리실 열쇠 정보
관리실 문 풀어
동 문 열어
동
문 봐
서 문 닫아
관리실 문 잠궈
```

`열어`·`닫아`·`잠궈`·`풀어`는 비전투 상태에서 같은 방의 감지 가능한 문만 조작한다. 고정 Alias는 추가하지 않는다. 정확한 이름·Alias·`동 문` 같은 방향·`문 2`를 지정하며, `문 열어`는 후보 하나일 때만 선택한다. 대상 없는 `열어`, 모호한 이름, `모두`는 거절한다. `동 봐`는 기존 Exit 정찰, `동 문 봐`는 개별 문 조회다. 일반 객체와 문 이름이 충돌하면 방향을 명시한다.

| 조작 | 관리실 외부 | 관리실 내부 | 회복실 양쪽 |
| --- | --- | --- | --- |
| 닫힌 문 열기 / 열린 문 닫기 | 열쇠 불필요 | 열쇠 불필요 | 열쇠 불필요 |
| 닫힌 문 잠그기 | 열쇠 필요 | 열쇠 필요 | 잠금 불가 |
| 잠긴 문 풀기 | 열쇠 필요 | 열쇠 없이 래치 허용 | 잠금 불가 |

잠긴 문은 먼저 풀고, 열린 문은 먼저 닫아야 잠글 수 있다. 중복 조작과 실패는 열쇠·상태·만료 시각을 바꾸지 않는다. `열어 도움`과 `열어 도움말` 등 네 명령의 상세 도움말은 같은 6개 섹션으로 제공한다.

## 시간·이동·조회

열기 성공 시각부터 60초 뒤 자동으로 닫힌다. 정상 통과마다 **통과 완료 시각+60초**로 연장하며 자동 잠금은 없다. 이미 열린 문에 다시 `열어`를 실행하거나 조회·실패 이동으로 연장하지 않는다. 정확히 만료 시각부터 논리적으로 닫혀 있으므로 5초 월드 tick이 늦어도 통과할 수 없다. 수동 닫기는 예약을 취소한다. 회복실 문은 최초 설치에만 OPEN이며 자동 재개방하지 않는다. 닫혔으면 양쪽에서 무료로 다시 열고 기존 침대의 `휴식`을 사용한다.

`봐`의 방 설명 뒤·환경 설명 앞에 감지 가능한 문의 상태를 자연어로 추가한다. 기존 제목·3×3 나침반·출구 안내의 구조를 유지하며 문 없는 방의 문자열은 바뀌지 않는다. 방향의 존재를 아는 것과 문 상태를 감지하는 것은 별개다. 닫힘·잠김·만료·손상된 문 뒤의 현재 설명·NPC·플레이어·적·물건·전리품·행동 힌트는 정찰과 웹에 공개하지 않는다. 열린 문에서도 기존 시야·Quest·view 권한은 적용한다.

`출구`는 기존 표에 현재 이동 가능 여부와 제한을 합성한다. `지도`는 방문 경로·공개 명칭의 기록이며 통과 가능성이나 원격 실시간 문 상태·자동 닫힘 시간을 새로 표시하지 않는다. 웹 조작은 기존 SURROUNDINGS/이동 버튼과 같은 텍스트 명령을 보내며 별도 RPC·메시지 종류·UI 컴포넌트는 없다. 오래된 버튼도 서버가 최신 상태와 권한을 다시 검사한다.

## 영속 상태와 최초 설치

`world/door_entities/models.py`의 Django `Door`가 한 물리 문의 상태를 소유한다. 양쪽 기존 Exit는 같은 `door_id`를 참조하며 원래 PK·방향·위치·목적지를 유지한다. 별도의 `DoorInstallation`은 원본 Door PK, 설치 시각, 양쪽 Exit/Room/목적지 PK를 보관한다. Door와 연결된 실제 Exit의 삭제는 PROTECT로 제한한다. Door가 소실돼도 설치 이력은 남아 신규 설치와 구별한다.

| ID | 연결 / 배치 | 최초 상태 |
| --- | --- | --- |
| `hq_admin_door` | `hq_concourse` 동 ↔ `hq_admin_office` 서 | LOCKED, 예약 없음 |
| `recovery_room_door` | `support_3f_e1` 북 ↔ `recovery_room` 남 | OPEN, 설치 시각+60초 |
| `hq_admin_key_cabinet` | `hq_lounge` | 정적 조사 객체 |
| `hq_admin_key` | Native ItemEntity 정의 | 미발급, 1인 1개 |

`0001_initial`은 두 테이블만 추가한다. 운영 적용은 백업·격리 복제 검증 후 정상 schema migration, 기존 서버의 월드 bootstrap 순서로 수행한다. 이 구현 작업에서는 실제 플레이 DB에 migration이나 bootstrap을 실행하지 않았다. 빈 격리 DB와 구 schema/실제 Room·Exit·Explorer·ItemEntity가 있는 SQLite 복제본에서 정상 migration과 데이터 보존을 검증한다. 프로필은 v14 그대로이며 데이터 변환·새 의존성은 없다.

## D13 복구와 진단

정적 `content/integrity.py::door_errors()`는 정의만 검사한다. `doors.installation_errors()`는 원본 PK·Typeclass·유일 Room tag·방향·목적지·설치 증거·상태·예약을 읽기 전용으로 검사한다. 정상 신규 설치, 정상 Door의 표시명/Alias 동기화, 원본 관계가 유일하게 입증된 참조 복원만 허용한다.

중복 결부, 설치 후 소실, 잘못된 상태·시각, 다른 Exit 결부, 목적지 손상은 OPEN 초기화·객체 재생성·임의 삭제·재연결로 해결하지 않는다. 해당 endpoint의 이동·조작·원거리 실시간 조회를 차단하고 서버 진단을 남긴다. 사용자에게 내부 PK·손상 상세·민감한 Quest 조건을 공개하지 않는다. 관계없는 정상 문/출구는 계속 동작한다. 기존 전체 bootstrap의 관리 Exit 충돌 preflight는 변경 전 실패를 유지하므로 관리자에게 진단을 확인하도록 한다.

## 트랜잭션과 전송

조작·열쇠 발급·만료 sweep은 기존 `world_change()`에서 조건을 재검증한다. 관리 Door 실제 Exit 이동은 바깥 변경 안에서 cmd/traverse Lock, Gate/Credential, 전투, 유효 OPEN 상태를 모두 검사하고 기존 `Explorer.move_to()`를 호출한다. 실제 도착지·출구 관계·완료 시각의 OPEN을 확인한 다음 연장한다. 위치·visited·예약이 함께 커밋되며 Hook 오류·False·다른 목적지·완료 시점 만료는 모두 롤백한다. 관리자 복구 등 비Exit 이동은 Door에 종속시키지 않는다.

성공 메시지·도착 화면·양쪽 접속자의 웹 상태는 `after_change()`로 최상위 커밋 이후 전달한다. 실제 열쇠함 `조사`를 포함한 GameCommand의 공통 상태 갱신도 이 경계를 따른다. 바깥 변경이 없는 일반 실행은 기존 대상·순서·횟수를 유지하고 상위/Savepoint 실패는 성공 콜백도 폐기한다. 새 Door 전송 콜백은 전송 예외를 서버에 기록하며 이미 커밋된 데이터를 되돌리지 않는다. 기존 Explorer 콜백의 전송 예외 전파 계약은 유지한다. 이 경우 DB 이동은 성공했어도 이후 화면 전송이 중단될 수 있으므로 전송 장애의 사용자 화면 복구는 운영/통합 검증에서 별도로 확인한다.

## 검증 경계와 후속

결정론적 시각으로 59.999/60초, 연속 통과, 늦은 tick, reload/restart reconcile, Savepoint와 최상위 롤백을 검사한다. 실제 지급·이동·권한을 Mock으로 대체하지 않고 외부 전송과 장애 주입만 관찰한다. 기존 Quest·Credential·일행·전투·Native/Legacy 전리품·회복실·v14 줄임말 회귀를 전체 검사에 포함한다.

실제 브라우저·OS 한글 IME·비색상 터미널·복수 실제 puppet 세션·장기 restart와 Cross-Issue E2E는 [Issue #50](https://github.com/wonmin82/primal-zone/issues/50)에 남긴다. 자동 DOM/WebSocket 이벤트 검증은 이러한 수동 검증을 대신하지 않는다. 이번 제출은 PR 리뷰 대기이며 Merge·브랜치 삭제·Issue 종료를 수행하지 않는다.
