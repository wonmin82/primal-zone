# 탐사 지도 Phase 1 검증

[범용 탐사 지도 설계 v2.2 FINAL](exploration-map-design-v2.2.md)은 [Epic #102](https://github.com/wonmin82/primal-zone/issues/102)의 규범적 본문 전체를 옮긴 문서다. 설계 시점의 상태와 체크리스트는 원본 그대로 기록되어 있다. 문서가 병합되면 지도 계약은 저장소 설계 문서를 기준으로 삼고, 승인과 변경 이력은 Epic에서 추적한다. 이 문서는 [Phase 1 #103](https://github.com/wonmin82/primal-zone/issues/103)의 실행 근거를 기록한다.

## 실제 월드

macOS 27.2.1 arm64, Python 3.13.18, Evennia 6.1.0, SQLite 3.53.1. 기준 `main`은 `01aaf8882824b8e34b76ad20d362af6cd4b31f61`이다. 테스트는 격리 DB에 실제 월드를 설치하고 각 Room에서 현재 지도 또는 Connector 출구를 조회한다.

| 대상 | Room 수 | 결과 |
|---|---:|---|
| 본부 1·2·3층 | 4 / 6 / 6 | 실제 Exit에서 자동 배치 |
| 본부 4·5층·옥상 | 9 / 11 / 9 | 실제 Exit에서 자동 배치. 옥상 8방향 포함 |
| 본부 계단·공용 승강기 | 6 / 1 | Connector의 실제 공개 출구 조회 |
| 탐사대 전초구역 | 8 | 자동 기본 Sheet, 지도 메타데이터 0건 |
| 깊은 밀림 | 7 | 자동 기본 Sheet, 지도 메타데이터 0건 |
| 합계 | 67 | 평면 60, Connector 7. Layout Hint 0건 |

일반 Region은 기존 Region과 Room·Exit만 등록하여 지도 엔진 변경과 지도 전용 선언 없이 처리한다. 합성 테스트에서 방향 순환, 두 경로가 만나는 Room, 분리 성분, 다층·Connector, 상대 Position·Route, 허용되지 않는 교차와 Room 관통을 검증한다. 동쪽으로만 이어져 출발점에 돌아오는 순환과 격자의 연결선이 가로지르는 구조는 일반적인 표현 불가 사례다.

## 재현 명령

```sh
.venv/bin/python scripts/dev.py check
.venv/bin/python scripts/dev.py test tests.test_exploration_map tests.bench_exploration_map --parallel 1
.venv/bin/python scripts/dev.py test --parallel 4
.venv/bin/python scripts/dev.py smoke
npm run test:contracts
.venv/bin/python scripts/browser_e2e.py
```

지도 통합 테스트는 Room 방문·이름 공개·Exit 공개의 독립 판정, 비공개 Hint 변경 시 공개 메시지 동일성, 원격 정적 Exit과 동적 Exit 구분, Door, 실제 대상 불일치, 동명 장소와 대형 허브, 조회 SQL의 쓰기 0을 검증한다. 명령 dispatcher에서 기존 Recovery와 Prompt를 유지하고 전역 상태 갱신을 추가하지 않는 것도 별도 검사한다. Quick Smoke는 실제 서버·WebSocket·스케줄러의 보조 회귀 검사다. 브라우저에서는 `TEST-103-01`로 기존 로그의 지도와 일반 출력의 줄바꿈을 각각 확인한다.

## 성능

명시적으로 실행하는 `tests.bench_exploration_map`은 서로 다른 10·100·1,000 Room 규모의 직선 Sheet에 실제 Evennia Room/Exit와 관리 태그를 구성한다. 원격 공개 범위의 그래프 구성·배치·렌더 각 단계를 계측한다. 시간은 추적을 끈 두 번째 단일 조회 한 번의 결과이며, 메모리는 별도의 추적 실행에서 Python 할당 피크를 기록한다. 동시 비용은 복제한 격리 SQLite에 독립 연결을 연 네 요청 묶음의 벽시계 시간이다. 이 측정은 실제 게임 서버의 이벤트 루프나 왕복 응답시간을 포함하지 않는다.

## 운영 및 범위

- 관리 Exit을 찾을 수 없고 기존 공개 정책을 판정할 실제 객체도 없으면 운영 로그에 불일치를 남기고 경계를 숨긴다. 공개된 관리 Exit의 목적지가 없거나 실제 목적지가 선언과 불일치하면 방문 여부에 관계없이 안전 실패 안내를 표시한다.
- 현재 구조의 Unicode 선문자는 기존 표시 폭 정책으로 1셀을 사용한다. 단말이 동아시아 모호 폭 문자를 2셀로 설정한 경우 `지도 ascii`로 확인할 수 있다.
- 전용 웹 미니맵은 [Phase 2 #104](https://github.com/wonmin82/primal-zone/issues/104) 범위다. Phase 1 PR 제출 시 G5의 병합·병합된 `main` CI 단계는 미완료다.

## PR #105 재검토와 최적화

시작 HEAD `75e5cc7acfab921a19fa6e4257c36b510976a316`, 기준 main `01aaf8882824b8e34b76ad20d362af6cd4b31f61`. 시작 작업 트리는 깨끗했고 이전 HEAD의 필수 검사는 Run 44870719246에서 모두 성공했다.

- 관리 Exit은 목적지 방문과 별개로 태그·타입·중복·실제 Room 관계를 검증한다. 공개 Exit의 목적지가 없거나 다르면 안전 실패로 끝난다. 숨긴 Exit의 손상은 사용자에게 같은 공개 결과를 유지하면서 운영 로그에 남긴다. 객체가 완전히 사라지면 view lock을 확인할 수 없으므로 누락 자체를 사용자 실패 신호로 사용하지 않는다. 범위에서 누락된 관리 태그의 출발지 이탈은 서버에서 별도 조회한다. 범위 밖에 있고 같은 태그를 공유하는 복제나 공식 저장 경계를 거치지 않은 외부 SQL 수정은 지도 요청이 수행하는 완전성 검사의 범위 밖이다.
- 기존 엔진·후치형 명령 구문과 접근 거절을 보존하고, 정확히 일치하는 고정 지도 옵션만 기존 후치 구문과의 충돌에서 우선한다. `지도 봐`, `지도 조사`, `지도 중심 봐`는 기존 대상을 받으며 `지도 목록`은 지도 옵션으로 실행된다.
- Sheet ID를 바꾸지 않고 빈 값, 공백, 제어 문자와 정규화 충돌을 정적으로 거절한다.

### 재현 조건

같은 벤치마크 파일을 시작 HEAD의 임시 아카이브와 보완 작업 트리에 적용했다. 위 최초의 단일 실행 수치는 역사적 기록이다. 이번 비교는 동일 환경·데이터에서 따로 재측정했다. 두 형상에서 `.venv/bin/python scripts/dev.py test tests.bench_exploration_map --parallel 1`을 실행했다. 콜드는 Evennia 객체 캐시를 비운 직후 한 건이며 OS·SQLite 파일 캐시까지 비운 값은 아니다. 웜은 계측기를 끈 20회 반복의 중앙값과 P95다. 보완 소스에서 측정한 Projection과 벤치마크의 Git blob은 각각 `7bccaab4896b`, `dba40a825f11`이다. SQL execute 시간은 별도 실행의 커서 execute 호출 누계이며, 잔여 시간에는 SQLite 행 fetch와 Python 처리가 모두 포함된다. 메모리는 별도 웜 실행에서 tracemalloc 피크를 기록했다. 동시 수치는 격리 SQLite 복사본을 읽는 4개 독립 연결의 한 묶음이다.

1,000 Room 전체 방문의 웜 중앙값은 85.0% 감소했다. 기존 cProfile에서 `load_rooms`는 176.392ms였고, 태그·Attribute가 SQL execute의 15.736ms를 차지했다. EXPLAIN은 기존의 범주·Attribute 키 선행 조합을 확인했다. 보완은 요청 태그 및 관계의 PK 인덱스를 출발점으로 사용하고, 추가 태그를 상관 EXISTS로 검사한다. Attribute는 실제 `zone_id` 값만 투영하고 중복 검사를 유지한다. 권한은 기존 실제 객체에서 판정하며 같은 요청에서 이미 읽고 판정한 Room을 재사용한다. 이에 따라 cProfile의 `load_rooms`는 15.522ms, ORM `from_db`는 4,998회·9.674ms에서 2,998회·4.447ms, `access`는 3,998회·23.753ms에서 2,998회·18.163ms로 감소했다. Exit 조회는 17.392→17.050ms였고 Projection 함수 본체의 자체 시간은 5.398→5.375ms였다. 프로파일 수치는 계측 오버헤드가 포함되므로 표의 웜 시간과 합산하지 않는다.

직선 9개와 본부 5층 전체·근처 2개의 공개 결과 지문이 전후 일치했다. 별도의 Connector·Sheet 경계 3개는 공개 노드·경계·공지 개수가 일치했다. 실제 최댓값인 본부 5층 11 Room의 Projection 중앙값은 전체 2.874→2.763ms, 근처 2.413→2.585ms였다. 작은 방문율 시나리오의 수백 µs 악화와 1,000 Room 100% 웜 메모리 약 2% 증가가 남았다. 동시 4건 wall은 단일 묶음이므로 운영 처리량을 의미하지 않는다. 합성 1,000 Room 순환·복수 경로 격자의 웜 배치/렌더는 70.112/3.960ms, Hint 1,996개 구조는 9.957/2.551ms였다. 순환 격자의 계측 프로파일에서는 `_find_conflicts`가 배치 비용 대부분을 차지했다. 장면과 격자 형상에 따른 배치 비용을 별도로 추적할 필요가 있다.

Room·Exit 전체 객체의 대체, 권한 SQL화, 영속 캐시, 인덱스 추가, 배치 알고리즘 교체는 적용하지 않았다. 현재 Sheet에서는 수 ms 규모였으며, 대형 단일 Sheet의 실제 지연·동시 부하 또는 게임 이벤트 루프 영향이 확인되면 공개 그래프 동등성을 증명하는 Bounded Projection을 별도 승인 대상으로 검토한다.

### Phase 2 인계

미니맵이 필요한 시점에 서버 공개 Projection을 요청하고, 실제 위치·방문 기록·공개 권한·조회 Sheet가 달라질 때와 현재 Door 표시가 바뀔 때 갱신한다. HP·전투 타이머·지도와 무관한 상태 갱신은 지도 계산을 유발하지 않는다. 전체 접속자 또는 전체 지도를 반복 전송하지 않으며 권한 갱신 뒤의 오래된 결과는 폐기한다. 서버 권한과 배치를 재사용하고, 클라이언트 지도 엔진이나 플레이어별 영속 Snapshot을 두지 않는다. 이 작업은 [Issue #104](https://github.com/wonmin82/primal-zone/issues/104)의 구현 범위를 유지한다.
