### B.2 실행 불변식 및 선택 계약 (R01~R14 / F01~F08)

- I01 영속성: 표시·선택·권한 변화로 임의 재번호하지 않는다. 순차 할당, 결번, 빈 그룹 초기화, 기존 번호 재사용 및 Scope/Group/DB 모델 불변.
- I02 정확성: B-1 명시 번호는 저장 Number이며 배열 인덱스가 아니다.
- I03 실행 안정성: 참조 확정 후 재선택 금지. 웹 Typed Reference는 발급 당시 Kind/Identity/Scope와 필요한 generation/lifecycle을 검증한다. 직접 입력 텍스트는 현재 문맥을 해석하며 과거 UUID의 영구 고정을 보장하지 않는다(F01).
- I04 표시 독립성: Display Label과 실행 문자열, TargetReference를 분리한다.
- I05 Scope 독립성: 번호 영역을 합치거나 재번호하지 않는다.
- I06 호환성: 상위 필수 계약과 충돌하지 않는 기존 명령을 유지한다. DEFAULT/ALL의 Loot 보완만 승인된 변경 범위에 포함하며 다른 도메인의 FIRST_LEGACY_ORDER/REQUIRE_UNIQUE/ALL 및 Legacy 정책을 일괄 변경하지 않는다.
- I07 Fail-closed: 무효·모호한 명시 선택을 다른 이름/Group/번호/Scope/UUID로 대체하지 않는다.
- I08 공개 관찰 동등성: 동일 Caller·Role/Scope·관찰 시각·공개 상태(공개 저장 번호 포함)·콘텐츠 정의·요청에서 비공개 실물 상태만 달라지면 허용된 공개 결과와 효과가 동일해야 한다. 공개 객체의 정상 실행 제한까지 숨기지 않는다.

| 모드 | 이름/후보 기준 | 실행 계약 |
|---|---|---|
| DEFAULT | 공개된 해당 명령의 후보, Loot는 회수 가능 후보 | 기존 Role의 기본 정책과 순서 |
| ALL | 공개 선택 후보, Loot는 회수 가능 후보 | 기존 범위의 일치 집합; 기존 named ALL의 정식 이름/별칭 규칙과 공개 Group 모호성 유지 |
| INDEX | 해당 명령 문맥, Loot는 기존 정적 이름 의미 및 Group 무결성 | 고유하게 확정한 Group의 저장 번호, 현재 권한 확인 |
| 정확 인용 | 정식 이름의 문자열 정확 일치 + 저장 번호 + 현재 공개 Role/Scope | 유일한 현재 대상; 실패 후 별칭/일반 입력으로 재해석 금지 |
| Typed Reference | 이름 파싱 없음 | 발급 당시 원래 참조만 검증 |

공개 객체의 존재/정체를 알아도 조작 권한이 없거나 수량·비용·전투 조건이 맞지 않을 수 있다. Public Set은 표시/관찰, Selection Set은 각 Role의 선택, Execution Set은 실행 검증에 사용한다. Loot의 기존 보호된 Entry 공개 정책 및 can_take_entry를 다른 도메인에 기계적으로 확대하지 않는다.

**F02 정적 이름 공간:** 기존 ITEMS의 Definition ID, Canonical Selection Name, aliases, normalized(), 실제 selection_group_id 또는 item:definition_id를 재사용한다. 기존 content/integrity.py의 alias_errors 및 번호 등록 시 같은 Scope의 정규화 정식 이름 충돌 검사를 검증한다. 동일 콘텐츠 정의에서 실물 유무에 따른 INDEX 의미 변화 금지. 정식 이름 우선, 고유 별칭 허용, 복수 Group 모호성은 안전한 공통 거절. 현재 없는 고유 대상과 숨은 대상은 동일 거절. 전체 내부 카탈로그를 플레이어 공개 목록으로 가정하지 않으며 비공개 정의를 오류/검색 기능으로 드러내지 않는다. 정적 판정은 실물/비공개 Claim 조회에 의존하지 않는다. 운영 진입점의 검사 강제 여부를 실제 확인한다. 캐시가 필요하면 기존 콘텐츠 생명주기를 사용하고 무효화를 검증한다.

**F03 파싱:** 유효한 인용 예약 구문 → 현재 공개된 실제 이름의 기존 우선 판정 → 일반 DEFAULT/INDEX/ALL 확정 → 일반 Loot INDEX의 정적 이름·Group 무결성 검사 → 현재 Scope에서 저장 번호 및 권한 확인. 비공개 실물은 known_names/literal_names 및 숫자 접미사·무효 인용 판정에 영향을 주지 않는다. 정적 카탈로그 전체를 일반 파서의 실명 후보로 일괄 전달하지 않는다. 기존 길이·번호 상한·이스케이프·관계 조사·통화 금액/번호 구분·비 B-1 문법 유지.

**F04 정확 인용 / Source:** 현재 공개 Role/Scope에서 정식 이름과 번호에 일치하는 대상 하나만 선택, 없음/복수면 거절. 비공개 객체를 공개 모호성 계산에 포함하지 않는다. 이미 확정된 Source/Group/참조는 다른 대상으로 대체하지 않는다. 서로 다른 Scope의 번호는 독립이다. 기존 문법에서 유일성이 불가능하면 실행 문자열 미제공, 유효한 Typed Reference 사용. `시체에서`는 기존 기본 공개 Source, `시체 2에서`와 `"시체" 2에서`는 명시 Source, `모든 시체에서`는 기존 공개 Source 범위, Source 생략은 기존 Ground 범위. 공개 시체의 내부 Entry 권리가 없다고 다른 시체로 자동 이동하지 않는다. 통화 금액, 지분, 보호 기한, 0원 지분의 유효한 트리거 및 원자적 지급 정책 유지.

**F05 번호 공개:** 기존 공개 객체의 저장 번호와 결번 및 할당 이력에 따른 제한적 추론은 허용. 테스트는 동일한 공개 저장 번호를 기준으로 비교하며 다른 할당 이력의 번호 차이 자체를 누출로 판정하지 않는다. 비공개 번호·정체·현재 존재/권한의 직접 구별은 금지한다.

**F06 공개 결과:** 메시지/상태/공개 오류 코드/Label/번호 표시/후보 순서/실행 문자열/웹 공개 Payload/공개 이벤트(종류·내용·순서)/선택된 공개 참조 및 도메인 효과를 비교한다. 임의 요청 ID와 서명 시각 등 비본질적 차이는 사전에 정의하고 제외한다. 서명은 암호화가 아니므로 클라이언트가 해석할 수 있는 Loot Snapshot 및 토큰 내용을 실제 공개 정책과 비교한다. 원시 토큰 바이트가 같을 필요는 없지만 디코딩 가능한 비공개 필드와 검증 의미는 확인한다. 서버 내부 로그 및 완전한 시간 동일화는 비교 범위 밖이다. 실제 중요 타이밍 누출은 별도 영향 평가. 공개 문법 오류 및 권한 확인 이후의 정상 도메인 오류 유지, 숨김/부재/Scope 불일치의 구별 불가능한 실패는 기존 target_unavailable()/LootUnavailable을 이용해 정규화한다. 모든 오류의 일괄 치환 금지.

표시 Snapshot은 동일 공개 관찰 문맥에서 읽기 전용이며 기존 합법적 선행 Room 생명주기 정합화와 구분한다. Display Label과 생성 명령은 분리한다. 기존 selection_text/action_command/loot_presentation.valid_command 등 실제 Resolver 왕복 검증을 사용하며 Source+Subject 전체 참조 및 수량까지 검증한다. 유일한 문자열이 없으면 제공하지 않는다. Gateway의 현재 Session/Puppet·Identity·Scope·Role·Provider·Capability·Owner·권리·수량 및 실행 직전 검증, 기존 잠금 순서/트랜잭션/Rollback 유지.

**F07 지원 및 심각도:** 정상 콘텐츠, Native 및 기존 지원 Legacy, 정상 이동/삭제/권한 변화/결번/재사용, 잘못된 입력·오래된 버튼·복수 Scope/Source는 필수 지원. 카탈로그 검사에서 거절되는 이름 충돌, 번호 행 누락, 잘못된 Group/참조/부모 관계는 최소 안전 실패와 잘못된 실행 금지. 검사 우회 Fixture의 안전한 실패는 비차단; 실제 운영 유입 가능성 및 영향을 근거로 분류하고 검사 함수 존재만으로 운영 불가능하다고 선언하지 않는다. 승인된 기존 ALL/INDEX 재현 및 수정은 유지한다. 정상 지원 범위의 정보 보호/선택 계약 위반은 P2 이상, 중요한 권한/실행 실패는 P1 이상, 광범위 권한 우회/데이터 손상/운영 불능은 P0 등 영향에 따라 판단. 비정상 데이터에서도 권한 없는 지급·잘못된 실행은 차단한다. 단순 방어 개선/사용성은 P3 또는 N/A. 운영 DB, 복수 서버 동시 쓰기, 이미 열린 구형 탭 수동 검증은 NOT RUN; OS 한글 IME는 기존 USER-CONFIRMED 재사용, 신규 파서 자동 검증 필수. 직접 손상 DB의 완전 복구는 별도 유지보수. 구형 문자열 버튼은 §8.7 갱신/재접속 경계 유지.

공개 상태 동등성은 독립 Fixture에서 같은 초기 공개 상태·번호·관찰 시각·콘텐츠·명령을 구성하고 비공개 상태만 변경한다. 공개 참조의 논리적 대응을 명시하고 실제 지급/공개 이벤트/권한 없는 효과 및 Rollback을 단언한다. 공개 상태 자체가 바뀐 경우 동일 성공을 요구하지 않고 해당 안전 계약을 검증한다. 기존 테스트를 재사용하고 필요한 반례만 추가한다. PASS/FAIL/N/A(사유)/UNVERIFIED/NOT RUN/OUT OF SCOPE를 구분한다. 필수 UNVERIFIED는 완료가 아니다.

### B.4 실행 계획 및 완료 Gate

기존 Phase 2 내에서 (1) 기준선/Manifest의 실제 경로 및 계약 매핑, (2) 구현 전 독립 Reviewer/Auditor의 반례와 지원 범위 검토·검증 매트릭스 확정, (3) 기존 미푸시 로컬 변경 보존 및 통합 수정/공통 회귀, (4) 확정된 전체 계약 기준 독립 리뷰, (5) 전체 테스트 및 PR #118 최종 HEAD CI를 수행한다. 기존 AGENTS.md, codex-multi-agent.md, codex-watch.md 준수. 구현 전 검토에서 실질적인 신규 정책 결정이 필요한 경우만 HOLD/승인 요청하며 승인 범위를 임의로 확대하지 않는다.
