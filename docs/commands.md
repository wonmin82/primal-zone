# 명령 어휘와 별칭 기준

실행 어휘의 SSOT는 미전환 기능의 Command `key`·`aliases`와 전환된 M01~M05의 Compiled Action Index `VerbDefinition`이다. `commands/aliases.py`의 전역 단축어와 `content/directions.py`의 방향은 유지한다. 콘텐츠는 `world/actions/`의 room_npc/item_equipment/storage/firearm_lighting/loot 패키지에 선언하며 정규 동사 하나당 Dynamic Command 하나가 현재 Provider의 Action을 선택한다. 넣어/꺼내 동사는 item_shared_content에서 한 번만 선언한다. 중앙 파서에 콘텐츠별 분기를 추가하지 않는다.

도움말은 미전환 Command의 `commands/help_contracts.py`·`help_sections`와 공개 Compiled Verb의 `summary`·`usage`·`category`·`help_sections`를 같은 렌더러에서 표시한다. 전환된 문·시설·NPC 서비스는 `room_npc_help.py`, 소비·장비·정보는 `item_equipment_help.py`, 총기·광원은 `firearm_lighting_help.py`, 보관은 공유 Verb 선언의 도움말을 사용한다. 요약·사용법·예시·실행 규칙·제한·관련 도움말과 별칭·분류를 유지하며, 도움말 조회는 Service를 실행하지 않는다. 전환 범위와 Legacy 제거 근거는 [Action 전환표](action-migration.md)를 따른다.

M01~M05의 조사·수리·문·소각·의료·상점·성장·정산·소비·장비·정보·보관·총기·광원·전리품은 운영 ContentPackage로 전환했다. 표의 `소각 확정`은 Dynamic Command의 공개 선택 키이며 실행 의미는 별도 SyntaxVariant다. 공개 접미어와 서버 확인 토큰을 검사하며 웹의 단순 `confirmed=true`로 우회하지 않는다. 가져/집은 Corpse/Ground Source의 공통 Action이다. 전역 봐·말·도움과 승인된 대화 경로는 유지한다.

ItemEntity의 `이름 2`는 B-1 번호 2, `이름 2개`는 수량이다. `붕대 2 1개 사용`은 2번 스택에서 한 번 소비하며 소비·착탈·주무기·정보는 복수 수량이나 모두를 다회 실행으로 확장하지 않는다. `개인 보관함에 붕대 모두 넣어`는 해당 품목 전체 스택 선택이고 웹 `스택 전부`는 표시된 UUID 하나다. 내부 탄창은 `경비카빈의 카빈표준 채워`처럼 부모 총기를 명시할 수 있다. 번호 결번·원격 보관품·이동한 웹 대상은 다른 대상으로 바뀌지 않는다.

대상·번호·조사는 별칭에서도 그대로 전달한다: `갈퀴사냥룡 2 쳐`, `보급관에게 붕대 구입`, `붕대 집`. 정식 명령·별칭으로 요청한 도움말은 같은 정식 페이지를 표시한다.

8방향 초성에 `ㅇ → 위`, `ㅁ/아 → 아래`를 더한다. 실제 출구가 있어야 이동하며 `나가`는 귀환으로 바꾸지 않는다. `시`는 `시체에서 모두 가져`, `시2`~`시5`는 `시체 N에서 모두 가져`다. 시야·번호·보호 시간·소유권·일행 분배를 그대로 적용한다.

`시체에서`는 기존 기본 시체 하나를 먼저 선택하고 `모든 시체에서`는 여러 출처를 선택한다. 출처 없는 `회수부품 가져`·`칩 2 가져`·`모두 가져`는 바닥 전리품을 선택한다. `칩 2`는 금액 2칩이 아니라 해당 범위의 화폐 항목 고정 번호 2이며, `20칩`은 회수 금액이다. 시체 번호와 내부 항목 번호는 별개이고, 결번이나 획득 권한 거절 때문에 다른 대상으로 바뀌지 않는다. `시2`는 살아 있는 고정 번호 2번 시체만 선택한다.


실제 명령과 Exit가 전역 고정·인자형 단축어보다 우선하고 개인 줄임말이 마지막이다. 잠긴 실제 명령도 개인 정의로 우회할 수 없다. 새 예약 이름과 충돌하는 저장 정의는 `_개인` 이름으로 보존하고 정확한 개인 호출 동사만 함께 옮긴다. 현재 장소의 특수 Exit와 충돌해도 Exit가 우선한다.

Evennia 기본 `look`, `inventory`, `help`, `who`는 새 사용자 명령과 중복되지 않도록 CmdSet에서 제거한다. 게임의 이동·접속 내부 관찰은 `at_look`을 직접 사용하므로 제거한 사용자 별칭을 요구하지 않는다. Account CmdSet에서도 기본 관찰·도움·접속자 명령을 제거해 게임의 새 이름을 우회하지 않는다.

엔진 호환 예외는 별도 `@help`다. Evennia 6.1의 엔진 도움·페이지 입력 완료 계약을 유지하는 동안 Character CmdSet의 `EngineHelp`가 이 이름만 등록하며 일반 영문 `help` 별칭은 복원하지 않는다. 플레이 가이드는 `도움`으로 확인한다. 페이지 추가 입력이 필요한 `@help`는 기존 줄임말/묶음 완료 검사에 따라 간접 실행을 거절하고 직접 입력하게 한다. 페이지 입력 없는 엔진 도움은 기존 완료 규칙을 따른다.

## 공개 NPC 대화와 개인 메시지

| 정식 명령 | 별칭·단축 | 역할·예시 |
| --- | --- | --- |
| `말` | `say`, 앞의 작은따옴표 `'` | 공개 채팅·NPC: `윤대장에게 임무 말`, `'윤대장에게 임무` |
| `대화` | 없음 | 온라인 플레이어 개인 메시지: `철수 안녕하세요 대화` |
| `대답` | 없음 | 최근 성공적으로 주고받은 개인 상대: `알겠습니다 대답` |
| `대화거부` | 없음 | 차단·해제: `철수 대화거부`; 단독 입력은 목록 |

기존 NPC용 `대화` Command/Action은 제거한다. NPC를 못 찾은 `에게` 문장은 원문 전체 공개, 복수 후보·잘못된 번호는 발화 없이 오류다. NPC는 정확한 선언형 Intent를 실행하고 임무 질문·진행 조회와 `수락`·`보고`·`재발급`을 분리한다. 22개 NPC의 서비스 명령은 그대로다. 공개 NPC 발화는 방에 동일 원문을 전달하고 키워드의 청록색 화제·황금색 행동 강조와 클릭 여부는 수신자별로 결정한다. 개인 임무 진행 응답과 보상·활성 입력 안내는 요청자에게만 전달한다.

`화제 안내`·`사용 가능한 화제`는 기존 인사 Intent의 읽기 전용 별칭이다. `윤대장에게 화제 안내 말`로 활성 입력을 다시 요청한다. 명시적 상대 또는 유효 문맥의 지시어를 포함한 후속 질문에 이해 실패 안내를 제공하며 실제 SSOT의 활성 읽기 전용 화제만 제시한다. 문맥의 연속 실패 안내는 한 번으로 제한하고 정상 대화 때 초기화한다. 개인 활성 목록은 첫 안내·목록 변경·명시적 요청·필요한 실패 안내에만 출력하며 공개 NPC 대사는 생략하지 않는다. 상세 경계는 [NPC 대화 설계](npc-dialogue.md#이해-실패와-화제-발견)를 따른다.

실제 CmdSet에서 확인한 Evennia `page`/`tell`과 `whisper`는 제거해 개인 차단 우회를 막는다. 엔진 내부 관리 기능을 추측으로 제거하지 않는다. 입력 우선순위와 줄임말 제한·부분 완료 계약은 유지한다. 사용자 예시는 [플레이 가이드](gameplay.md#npc-대화와-개인-메시지), SSOT·토큰·문맥·저장 계약은 [NPC 대화 설계](npc-dialogue.md)를 따른다.

## 문 조작

`관리실 문 열어`, `동 문 닫아`, `관리실 문 잠궈`, `관리실 문 풀어`의 후치형입니다. 감지 가능한 한 문은 `문`으로 지정할 수 있지만 무인자는 거절합니다. 개별 `동 문 봐`와 기존 Exit `동 봐`를 구분합니다. 열쇠함은 기존 `조사`, 열쇠 설명은 기존 `정보`를 사용합니다. 신규 네 명령 및 `조사`·`봐`·`출구`·`지도`·`정보`의 상세 도움말은 6개 섹션을 제공하며 `도움`/`도움말`은 같은 페이지입니다. v14와 기존 실제 명령/Exit 우선순위를 유지합니다. [문·열쇠 계약](doors-and-keys.md)을 참고하세요.

## 저장 정의 변환

46-A 커밋에서는 profile v11을 유지하고 변환 함수만 준비했다. `정보`의 기존 상태 조회 의미와 `진료`의 기존 의료 기능은 각각 46-B·C에서 한 번에 전환한다. 46-C에서 모든 새 명령의 구현을 완료한 뒤 당시 profile v12로 전환했다. v12 이상 정의에는 과거 어휘 변환을 다시 적용하지 않는다. 현재 profile은 v14이며 기존 [v13 NPC 방법 B](command-shortcuts.md#프로필-v13의-npc-대화-이전)에 [v14 일행 명령 이전](command-shortcuts.md#프로필-v14의-일행-명령-이전)을 추가한다.

v7 이하의 `회복`은 먼저 기존 v8/v10 변환을 거쳐 붕대 응급처치 의미를 보존한다. v11 이하의 `정보`는 `점수`, `진료`는 새 `회복`, `사격`은 `쏴`로 변환한다. v8~v11에 남은 구 `회복`도 붕대 응급처치로 보존하고 새 v12의 `회복`은 유료 의료 의미다. 이전 단독 명령에 대상을 붙인 정의 등 의미가 불명확한 입력은 원본과 재등록 사유를 담은 비활성 항목으로 보존한다. 채팅·객체명·변수는 바꾸지 않고 정의의 동사 자리만 변환한다. 불명확하거나 비정상인 원본은 삭제하지 않고 기존 비활성/관리자 복구 안내를 유지한다.

## 검증 범위

아래는 Issue #46에 적용한 정책(2026-10-10 갱신)의 기록이다. #47의 게이트는 이 절 끝의 별도 정책을 따른다. #46 정책은 개발 중 경량 검증과 Push 전 전체 로컬 CI를 구분한다. 46-A·B·C 내부 개발 중에는 변경 범위의 격리 DB 대표 Smoke를 수행하고 단계별 로컬 커밋을 허용한다. 커밋마다 전체 회귀를 반복하지 않는다.

Issue #46의 원격 Push 또는 PR 생성·업데이트 직전에는 실제 Push할 커밋 HEAD에서 현행 `.github/workflows/tests.yml`과 동등한 로컬 CI 전체를 통과해야 한다. 현재 필수 명령은 다음과 같다.

```powershell
uv sync --locked --python 3.13
uv run python scripts/dev.py check
uv run python scripts/dev.py test --parallel 2
uv run python scripts/dev.py smoke
```

하나라도 실패하거나 실행하지 못하면 Push하지 않는다. 검사 이후 코드가 바뀌면 변경된 HEAD에서 전체 로컬 CI를 다시 수행한다. 실제 환경·명령·종료 코드·테스트 수·검증 SHA를 [PR #51 Validation](https://github.com/wonmin82/primal-zone/pull/51)에 기록하고, Push 후 같은 HEAD의 GitHub Actions `test`·`smoke` 결과를 별도로 확인한다. 원격 실패를 수정한 커밋도 다시 로컬 CI 게이트를 통과해야 한다.

여러 Issue의 통합 시나리오·실 브라우저·한글 IME·복수 플레이어/세션 경합·도움말/UI 종단 간 검사·최종 통합 회귀는 #50에서 수행한다. #50의 별도 검증은 #46의 Push 전 전체 로컬 CI 의무를 대체하지 않는다. 상세 이력은 [테스트 안내](playtest.md#issue-46-pr-51-리뷰-후-검증-정책-2026-10-10)를 참고한다.

### Issue #47의 현재 검증 정책

개발 중에는 변경 범위의 경량 테스트·콘텐츠 검사·웹 자동 테스트를 수행한다. Push 전에는 실제 커밋 HEAD에서 `uv run python scripts/dev.py smoke`의 격리 Quick을 필수 통과한다. 실패·미실행이면 Push하지 않는다. 실행 코드·테스트가 바뀌면 새 HEAD에서 Quick을 다시 실행한다. 로컬 전체 회귀를 중복 실행하지 않으며 Push 후 해당 HEAD의 GitHub Actions 전체 `test`·`smoke`를 확인한다. 실 브라우저·OS 한글 IME·Cross-Issue 통합·복수 사용자 E2E는 #50에서 추가 검증한다.

### 최초 구현 당시의 경량 검증 이력

아래는 최신 사전 CI 정책이 적용되기 전의 실제 실행 기록이다. 당시 미실행한 전체 로컬 검사와 이후 자동 CI를 구분하며, 현재 Push 허용 조건으로 사용하지 않는다.

46-A: `.venv/Scripts/python.exe scripts/dev.py test tests.test_command_overhaul.CommandOverhaulSmoke.test_phase_a --parallel 1` 성공(대표 Smoke 1개). 정식 명령·별칭·상점·방향·시체 입력·shooting 예약·개인 정의 변환·도움말 섹션/별칭을 확인했다. `ruff check game scripts`, JavaScript `node --check`, `git diff --check` 통과. 로컬 전체 회귀·실 브라우저·서버 전체 smoke는 요청 범위에 따라 미실행했다.

46-B: 같은 격리 검사 경로의 `test_phase_b --parallel 1` 성공(대표 Smoke 1개). 장착/동명 번호 무기·삽입 탄창 잔탄·붕대·손전등·정보 도움을 조회하고 실제 ItemEntity 전체와 저장 프로필이 변하지 않음을 확인했다. 상태용 정보 별칭 제거와 신규 명령 등록을 동시에 적용했다.

46-C: `test_phase_c --parallel 1` 성공(대표 Smoke 1개). 전량·부분 HP와 레벨별 비용, 잔액 부족·잘못된 수량·저장 예외의 HP/칩 rollback, SP 자연회복 경계에서도 의료 요청 자체의 SP 불변, 같은 침대 객체의 회복실 이전·반복 bootstrap·무료 휴식을 확인했다. 최종 v12 마이그레이션의 과거 회복/진료/사격 의미와 불명확한 원본 보존·재적용 불변도 확인했다.

최종 대표 검사 `tests.test_command_overhaul --parallel 1`은 A/B/C 3개 모두 성공했다. 이후 원본 보존 보완에 영향을 받는 C 1개를 다시 확인했다. 전체 게임 테스트·실 서버 Quick/Full smoke·브라우저는 실행하지 않았으며 자동 CI는 PR의 최신 HEAD 결과로 별도 확인한다.
