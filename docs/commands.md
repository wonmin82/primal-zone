# 명령 어휘와 별칭 기준

실행 어휘의 SSOT는 각 Command의 `key`·`aliases`, `commands/aliases.py`의 전역 단축어와 `content/directions.py`의 방향이다. 도움말의 표시 입력은 `commands/help_contracts.py`와 개별 명령의 `help_sections`를 사용한다.

| 정식 명령 | 사용자 별칭 | 제거한 이전 입력 |
| --- | --- | --- |
| 봐 | 본, 보, ASCII 0x60 백틱 | 보기, look, l, 둘러보기 |
| 도움 | 도움말 | 안내, ? |
| 점수 | 상태, 상, 점 | stat, 상태 조회용 정보 |
| 가진거 | 가진, 소, 소지, 소지품 | 가방, i, 인벤토리 |
| 누구 | 누 | 접속자, who |
| 때려 | 쳐, 공격 | 사냥, attack |
| 목록 | 품목, 품, 목, 메뉴 | 상품 |
| 사 | 구입 | 구매, buy |
| 팔아 | 팔, 판 | 판매, sell |
| 쏴 | 없음 | 사격, shooting |
| 지도 | 지 | map |
| 경험치 | 경 | 없음 |
| 장비 | 장 | 없음 |
| 착용 | 입어, 입 | wear |
| 벗어 | 벗 | remove |
| 가져 | 집 | 없음 |
| 줄임말 | 준말 | 없음 |
| 가치 | 얼마 | value |
| 정보 | 없음 | 이전 상태 조회 의미 제거 |
| 회복 | 없음 | 진료, treat |

대상·번호·조사는 별칭에서도 그대로 전달한다: `갈퀴사냥룡 2 쳐`, `보급관에게 붕대 구입`, `붕대 집`. 정식 명령·별칭으로 요청한 도움말은 같은 정식 페이지를 표시한다.

8방향 초성에 `ㅇ → 위`, `ㅁ/아 → 아래`를 더한다. 실제 출구가 있어야 이동하며 `나가`는 귀환으로 바꾸지 않는다. `시`는 `시체에서 모두 가져`, `시2`~`시5`는 `시체 N에서 모두 가져`다. 시야·번호·보호 시간·소유권·파티 분배를 그대로 적용한다.

실제 명령과 Exit가 전역 고정·인자형 단축어보다 우선하고 개인 줄임말이 마지막이다. 잠긴 실제 명령도 개인 정의로 우회할 수 없다. 새 예약 이름과 충돌하는 저장 정의는 `_개인` 이름으로 보존하고 정확한 개인 호출 동사만 함께 옮긴다. 현재 장소의 특수 Exit와 충돌해도 Exit가 우선한다.

Evennia 기본 `look`, `inventory`, `help`, `who`는 새 사용자 명령과 중복되지 않도록 CmdSet에서 제거한다. 게임의 이동·접속 내부 관찰은 `at_look`을 직접 사용하므로 제거한 사용자 별칭을 요구하지 않는다. Account CmdSet에서도 기본 관찰·도움·접속자 명령을 제거해 게임의 새 이름을 우회하지 않는다.

엔진 호환 예외는 별도 `@help`다. Evennia 6.1의 엔진 도움·페이지 입력 완료 계약을 유지하는 동안 Character CmdSet의 `EngineHelp`가 이 이름만 등록하며 일반 영문 `help` 별칭은 복원하지 않는다. 플레이 가이드는 `도움`으로 확인한다. 페이지 추가 입력이 필요한 `@help`는 기존 줄임말/묶음 완료 검사에 따라 간접 실행을 거절하고 직접 입력하게 한다. 페이지 입력 없는 엔진 도움은 기존 완료 규칙을 따른다.

## 저장 정의 변환

46-A 커밋에서는 profile v11을 유지하고 변환 함수만 준비했다. `정보`의 기존 상태 조회 의미와 `진료`의 기존 의료 기능은 각각 46-B·C에서 한 번에 전환한다. 46-C에서 모든 새 명령의 구현을 완료한 뒤 현재 profile v12로 전환했다. 최신 v12의 정의에는 과거 어휘 변환을 다시 적용하지 않는다.

v7 이하의 `회복`은 먼저 기존 v8/v10 변환을 거쳐 붕대 응급처치 의미를 보존한다. v11 이하의 `정보`는 `점수`, `진료`는 새 `회복`, `사격`은 `쏴`로 변환한다. v8~v11에 남은 구 `회복`도 붕대 응급처치로 보존하고 새 v12의 `회복`은 유료 의료 의미다. 이전 단독 명령에 대상을 붙인 정의 등 의미가 불명확한 입력은 원본과 재등록 사유를 담은 비활성 항목으로 보존한다. 채팅·객체명·변수는 바꾸지 않고 정의의 동사 자리만 변환한다. 불명확하거나 비정상인 원본은 삭제하지 않고 기존 비활성/관리자 복구 안내를 유지한다.

## 검증 범위

Issue #46의 현재 정책(2026-10-10 갱신)은 개발 중 경량 검증과 Push 전 전체 로컬 CI를 구분한다. 46-A·B·C 내부 개발 중에는 변경 범위의 격리 DB 대표 Smoke를 수행하고 단계별 로컬 커밋을 허용한다. 커밋마다 전체 회귀를 반복하지 않는다.

원격 Push 또는 PR 생성·업데이트 직전에는 실제 Push할 커밋 HEAD에서 현행 `.github/workflows/tests.yml`과 동등한 로컬 CI 전체를 통과해야 한다. 현재 필수 명령은 다음과 같다.

```powershell
uv sync --locked --python 3.13
uv run python scripts/dev.py check
uv run python scripts/dev.py test --parallel 2
uv run python scripts/dev.py smoke
```

하나라도 실패하거나 실행하지 못하면 Push하지 않는다. 검사 이후 코드가 바뀌면 변경된 HEAD에서 전체 로컬 CI를 다시 수행한다. 실제 환경·명령·종료 코드·테스트 수·검증 SHA를 [PR #51 Validation](https://github.com/wonmin82/primal-zone/pull/51)에 기록하고, Push 후 같은 HEAD의 GitHub Actions `test`·`smoke` 결과를 별도로 확인한다. 원격 실패를 수정한 커밋도 다시 로컬 CI 게이트를 통과해야 한다.

여러 Issue의 통합 시나리오·실 브라우저·한글 IME·복수 플레이어/세션 경합·도움말/UI 종단 간 검사·최종 통합 회귀는 #50에서 수행한다. #50의 별도 검증은 #46의 Push 전 전체 로컬 CI 의무를 대체하지 않는다. 상세 이력은 [테스트 안내](playtest.md#issue-46-pr-51-리뷰-후-검증-정책-2026-10-10)를 참고한다.

### 최초 구현 당시의 경량 검증 이력

아래는 최신 사전 CI 정책이 적용되기 전의 실제 실행 기록이다. 당시 미실행한 전체 로컬 검사와 이후 자동 CI를 구분하며, 현재 Push 허용 조건으로 사용하지 않는다.

46-A: `.venv/Scripts/python.exe scripts/dev.py test tests.test_command_overhaul.CommandOverhaulSmoke.test_phase_a --parallel 1` 성공(대표 Smoke 1개). 정식 명령·별칭·상점·방향·시체 입력·shooting 예약·개인 정의 변환·도움말 섹션/별칭을 확인했다. `ruff check game scripts`, JavaScript `node --check`, `git diff --check` 통과. 로컬 전체 회귀·실 브라우저·서버 전체 smoke는 요청 범위에 따라 미실행했다.

46-B: 같은 격리 검사 경로의 `test_phase_b --parallel 1` 성공(대표 Smoke 1개). 장착/동명 번호 무기·삽입 탄창 잔탄·붕대·손전등·정보 도움을 조회하고 실제 ItemEntity 전체와 저장 프로필이 변하지 않음을 확인했다. 상태용 정보 별칭 제거와 신규 명령 등록을 동시에 적용했다.

46-C: `test_phase_c --parallel 1` 성공(대표 Smoke 1개). 전량·부분 HP와 레벨별 비용, 잔액 부족·잘못된 수량·저장 예외의 HP/칩 rollback, SP 자연회복 경계에서도 의료 요청 자체의 SP 불변, 같은 침대 객체의 회복실 이전·반복 bootstrap·무료 휴식을 확인했다. 최종 v12 마이그레이션의 과거 회복/진료/사격 의미와 불명확한 원본 보존·재적용 불변도 확인했다.

최종 대표 검사 `tests.test_command_overhaul --parallel 1`은 A/B/C 3개 모두 성공했다. 이후 원본 보존 보완에 영향을 받는 C 1개를 다시 확인했다. 전체 게임 테스트·실 서버 Quick/Full smoke·브라우저는 실행하지 않았으며 자동 CI는 PR의 최신 HEAD 결과로 별도 확인한다.
