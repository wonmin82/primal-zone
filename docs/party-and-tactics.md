# 일행과 전술 — Issue #48 v2.2 FREEZE

기존 Party 영속 객체를 유지하며 일행 명령과 관리 서비스를 확장한다. 내부 Typeclass 경로와 개인별 확정 전리품 권리는 변경하지 않는다.

## 생성과 가입

`일행모으기`는 미가입·비교전 플레이어의 1인 일행을 만든다. `철수 일행초청`도 같은 생성 경로를 사용한다. 초청이 거절되거나 만료되어도 1인 일행은 유지한다.

리더는 온라인 미가입 타인을 초청하며, `일행합류`는 유효 초청 수락만 처리한다. `철수 일행요청`은 온라인인 기존 리더에게 가입 요청을 보낸다. 리더는 `민수 일행허락` 또는 `민수 일행거절`로 처리한다. `일행거절` 단독 입력은 자기 초청 거절이다.

초청과 발신 요청은 각각 한 건이며 동시에 보유할 수 있다. TTL은 60초이고 `now >= expires_at`부터 만료다. 반복 입력으로 연장하지 않는다. 실제 가입과 명시적 생성 성공 시 다른 대기 상태를 같은 `world_change()`에서 정리한다. 정원 4명, 미가입·비교전·온라인 조건은 승인 직전에 재검증한다. 요청자가 오프라인이면 요청을 삭제하지 않는다. 초청 수락에는 리더의 온라인 상태를 요구하지 않는다.

## 관리와 해체

`철수 일행리더`는 명시적 위임이고, `철수 일행제외`는 리더의 타 구성원 제외다. `일행탈퇴` 시 기존 `leave_combat()`을 호출한다. 리더가 탈퇴하면 가입 순서 첫 멤버가 승계한다.

`일행해체` 후 60초 내 `확인 일행해체`로 확정한다. 비영속 확인은 일행 ID·리더 ID·멤버 ID/가입 순서에 결합한다. 실제 유효 교전이 있으면 요청·확인 모두 거절한다. 오래된 프로필 target 값만으로 교전이라고 판단하지 않는다.

해체 또는 마지막 멤버 탈퇴 전 Native/Legacy 개인 권리를 검사한다. `assigned_player`, `reserved_player`, 화폐 지분과 보호 만료 시간은 보존하고, 과거 일행의 공동 회수 권리만 제거한다. 개인 권리를 보존할 수 없는 비정상 보호 데이터는 삭제를 중단한다. Native의 `reserved_party SET_NULL` 및 개인 참조 `PROTECT`를 따른다.

해체 후에도 배정된 실물은 원래 수령인에게 전달된다. 보호된 화폐를 적법하게 회수하면 요청량을 남은 개인 지분에 따라 함께 지급하며 회수자가 독점하지 않는다. 보호 만료 뒤에는 기존 자유 획득 규칙을 적용한다. Native `loot_service.pickup()`과 Legacy `take_loot()`의 실제 수령·부분 지급·중복 차단·롤백 회귀 검사를 [RT-15/16 추적](issue48-requirement-tests.md#pr-53-최종-리뷰-추가-검증)으로 연결한다. 지급·가격·분배 정책은 변경하지 않았다.

## 리더 오프라인 승계

온라인 일반 멤버는 리더의 실제 활성 puppet 세션이 모두 종료된 직후 `일행승계`로 자신에게 리더를 즉시 옮길 수 있다. AFK는 대상이 아니다. Party의 `leader_offline_since`에서 연속 600초가 경과하면 기존 WorldLifecycle의 첫 정상 5초 tick에서 가입 순서가 가장 빠른 온라인 멤버가 자동 승계한다.

후보가 없으면 기존 리더와 시작 시각을 유지한다. 이후 후보의 접속 훅에서도 승계 조건을 재검증한다. 기존 리더가 먼저 재접속하면 대기를 취소한다. 이전 리더의 권한은 재접속으로 복원하지 않는다. 일행 ID·멤버 순서·초청·요청·분배·커서·방어 담당은 유지하고 해체 확인을 무효화한다.

마지막 unpuppet과 접속 훅은 같은 재검증 경로를 사용한다. 누락된 시각은 최초 신뢰 가능한 관측부터 기산한다. `ServerConfig.server_restart_mode`가 존재하는 동안은 Portal 세션 전체 동기화 전이므로 오프라인 판정을 보류한다. Evennia 6.1은 동기화 완료 후 이 값을 삭제하므로 reload의 일시적 재바인딩을 접속 종료로 오판하지 않는다.

48-B2 검증: 실제 600초 대기 없이 주입 시각과 0/1/2개 puppet 세션, reload 표지, cold restart/world reconcile 호출로 RT-17~27 경계를 검증했다. 누적 `tests.test_party_overhaul` 17개 통과. 48-B 커밋 당시 `git diff --check`는 테스트 파일 끝 빈 줄 경고가 있었으며 이번 단계에서 제거하고 재검사했다. 해당 경고를 제외한 단계 테스트는 통과했다.

## 일행대화

`모여 주세요 일행대화`와 `무리말`·`그룹대화`·`무`는 발신자를 포함한 현재 온라인 멤버에게만 `[일행] 이름: 내용`을 보낸다. 다른 방에서도 수신하며 개인 차단·최근 개인 대화 상대와 무관하다. #47의 300자·ANSI/제어문자 검증과 `Text(kind="chat")`를 재사용한다. 본문을 저장하거나 NPC/명령으로 재실행하지 않는다.

발신 당시 멤버 ID를 확보하고 커밋 후 전달마다 발신자·수신자의 현재 멤버십을 재검증한다. 중간 탈퇴·제외·해체 시 이전 구성원에게 누출하지 않는다. 네트워크 전달 실패는 본문 없이 기록한다.

48-C: `tests.test_party_overhaul.PartyChatTests` 2개 통과. 다른 방·외부 격리·차단 무관·본문 검증·전달 전 탈퇴 및 해체를 확인했다.

## 일행공격

`어린청소룡 일공`은 리더가 같은 장소의 적을 적법하게 식별한 뒤 가입 순서대로 참가 조건을 검사한다. 무인자 `일행공격`은 리더의 현재 적을 사용한다. 다른 적과 교전 중인 리더도 지시할 수 있지만 자신은 불참한다.

현재 멤버·온라인·동일 장소·생존·개별 시야·Claim·현재 적을 각각 재검증한다. 신규 참가자는 기존 `start_combat()` → `Enemy.engage()`를 사용한다. 같은 적 기존 참가자는 재시작하지 않는다. 예상된 불참은 나머지 멤버를 막지 않고, 예외적인 DB/런타임 오류는 실제 완료 결과를 알린 뒤 후속 처리를 중단하고 오류를 드러낸다.

지시 자체로 피해·탄약·정신력·XP를 변경하지 않는다. 기존 2.5초 주기·예약 행동·기여도·Claim·보스 스케일링을 유지한다. 중첩 원자적 변경에서도 타이머와 참가 알림은 커밋 후 실행한다.

48-D: `tests.test_party_overhaul.PartyAttackTests` 4개 통과. 기존 참가/다른 적/다른 방/신규 참가 혼재, 멱등·전원 불가·런타임 중단, 권한·시야·외부 Claim, 실제 교전 해체 거절을 검증했다. 첫 실행은 fixture의 월드 관측 시간이 가짜 전투 시각과 달라 만료를 유발했으며 동일한 주입 시각으로 정리한 뒤 통과했다.

## 영속 일행방어

`철수 일행방어`는 리더가 `Party.tactics.defender_id`에 멤버 ID 하나를 저장한다. 오프라인·다른 장소·현재 교전 여부를 지정 조건으로 요구하지 않는다. 조회 `일행방어`는 모든 멤버가 가능하며 `해제 일행방어`는 제어어가 우선한다. 이름이 해제인 멤버는 `해제 1 일행방어`로 지정한다. 같은 지정·빈 설정 해제는 멱등이다.

Enemy AI는 먼저 기존 최고 위협도 내림차순·ID 오름차순 기본 대상을 선정한다. 그 대상의 현재 일행 담당자가 같은 Enemy의 유효 참가자이고 온라인·생존·같은 장소·같은 적 교전·Claim 조건을 만족할 때만 최종 대상을 바꾼다. 다른 일행이나 솔로의 우선권을 가로채지 않는다. 피해·방어·위협도·주기·XP·Loot·보스 HP는 변경하지 않는다.

전투 종료·도망·패배·이동·오프라인·재접속·reload/restart·리더 변경은 효과만 비활성화할 수 있고 저장된 지정을 지우지 않는다. 명시적 해제·교체·담당자 탈퇴/제외·영속 객체 삭제·일행 해체만 지정을 제거한다. 다음 유효 교전에서 자동 적용하며 재가입은 과거 지정을 복구하지 않는다.

48-E: `tests.test_party_overhaul.PartyDefenseTests` 5개 통과. 권한·오프라인/해제 동명 선택·멱등, 실제 enemy tick의 대상 변경과 수치 보존, 다른 일행/솔로 보호, 전투 이탈·shutdown 복원·리더 변경·탈퇴 및 깨진 ID 정리를 확인했다.

## 웹과 저장 정의 호환성

기존 pz_state의 일행 패널은 Party ID·리더·접속/승계 상태·4인 정원·초청/가입 요청·분배·영속 담당·현재 방어 효과를 구별한다. 현재 멤버십에 따른 버튼과 초청/요청·대화 입력창으로 [16개 명령](commands.md#일행-명령-16개)에 접근한다. 버튼은 기존 텍스트 명령 경로만 사용하고 서버가 권한·대상·TTL을 다시 검사한다. 이름은 안전한 DOM 텍스트로 표시한다. 자동 승계는 알림 후 최신 상태를 전송한다.

웹 승계 버튼과 상태 설명도 `sessions_ready()` 및 현재 멤버의 실제 puppet 접속 조건을 따른다. Portal 재바인딩 중에는 승계 불가이며 완료 뒤 다시 평가한다. 상태 스냅샷은 만료된 대기를 제외하되 Party TTL·오프라인 시각을 저장하거나 정리하지 않는 읽기 전용 조회다.

초청·가입 요청은 같은 스냅샷의 서버 시각 `server_now`와 `expires_at`으로 남은 초를 계산한다. 0 미만을 표시하지 않고 정확한 만료 시각부터 만료로 취급한다. `42초 남음 (수신 기준)`은 실시간 카운트다운이 아니며 새 서버 상태를 받을 때 갱신한다. 로컬 시계와 별도 타이머에 의존하지 않는다. 만료된 스냅샷의 합류·승인 버튼은 제공하지 않으며, 화면이 오래되었더라도 실제 실행은 서버 TTL 검사로 거절한다. 이전 payload에 시각이 없으면 남은 시간 재확인이 필요하다고 표시한다.

프로필 v14는 기존 v13 방법 B를 보존하고 구 일행 명령의 동사 위치만 이전한다. 변수·채팅 본문·사용자 인자는 바꾸지 않는다. 새 명령/별칭 충돌과 위험한 묶음/간접 참조는 원본을 보존한다. 자세한 계약은 [개인 줄임말 이전](command-shortcuts.md#프로필-v14의-일행-명령-이전)을 따른다. Party Typeclass·기존 ID·멤버 순서·전리품 커서와 게임 수치는 유지한다.

## 검증 추적과 후속 경계

[RT-01~RT-47 추적표](issue48-requirement-tests.md)에 Decision·실제 코드·테스트 이름·실행 결과를 연결한다. 개발 중 직접 영향 검사를 사용하고 최종 커밋의 격리 Quick 성공 후에만 Push한다. 이후 최신 PR HEAD의 원격 전체 CI를 확인한다. 로컬 전체 회귀·실 브라우저·IME·실 다중 세션 E2E는 실행한 것으로 기록하지 않는다.

#49 문/열쇠 기능은 구현하지 않는다. RT-47의 실제 브라우저·IME·복수 세션·Cross-Issue 및 최종 통합은 #50에 이관한다. 기존 단일 Evennia 서버의 world_change 직렬 변경 전제를 유지하며 별도 Party/전투/메시징 엔진은 만들지 않는다.
