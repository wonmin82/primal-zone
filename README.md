# 원시구역 · Primal Zone

사냥하고 장비를 모으며, 잊힌 섬을 탐험하는 한국어 웹 MUD.
사냥·장비·성장을 우선하고, 모든 주요 임무를 혼자 진행할 수 있도록 만든다.

Item System V1의 Phase 1~7C를 완료했다. [PR #37](https://github.com/wonmin82/primal-zone/pull/37)과 [test-only CI 안정화 PR #38](https://github.com/wonmin82/primal-zone/pull/38)을 병합하고 새 main exact-head test·smoke 성공을 확인했다. 최종 상태는 **ITEM SYSTEM V1 COMPLETE**다. 지원 topology는 SQLite + single Evennia server이며, PostgreSQL/multi-server·외부 배포와 HTTPS/WSS/TLS·production monitoring·legacy adapter/field/archive 정리와 기타 product roadmap은 별도 후속 작업이다. [최종 콘텐츠](docs/final-content.md), [밸런스 분석](docs/phase7c-balance-analysis.md), [fresh 검증](docs/phase7c-fresh-operational-validation.md), [최종 마감 근거·제한 사항](docs/CODEX_TASK_STATE.md)을 참고한다. 최종 문서 PR 병합 뒤 저장소 HEAD의 CI·브랜치 정리 결과는 해당 PR Validation에 기록한다.

## 실행

기존 DB는 이 버전으로 서버를 시작하기 전에 [아이템 migration 운영 절차](docs/item-migration.md)를 완료한다. 새 빈 DB는 ItemEntity 기반으로 직접 시작한다.

현재 전환해야 할 실제 플레이 DB는 없으며 새 플레이는 fresh native DB로 시작한다. Phase 7의 검증 범위는 [통합·마감 audit](docs/phase7-final-integration-audit.md)을 따른다.

처음 설치한다면 [설치 안내](docs/installation.md)에서 필요한 환경, Git·uv 설치, 저장소 다운로드와 초기 설정부터 확인한다.

Python 3.13과 [uv](https://docs.astral.sh/uv/getting-started/installation/)를 사용한다.
저장소 루트에서 실행:

```sh
uv sync --locked --python 3.13
uv run python scripts/dev.py setup
uv run python scripts/dev.py start
```

[로컬 게임 화면](http://127.0.0.1:8701/webclient/)을 열고, 이름과 비밀번호를 정한 뒤 **새 탐사자 만들기**를 선택한다.
첫 서버 시작은 초기 설정 때문에 약간 기다려야 할 수 있다.

이미 가상환경이 구성된 Windows에서는 uv 대신 다음처럼 실행할 수 있다:

```powershell
.\.venv\Scripts\python.exe scripts/dev.py start
```

프로젝트 기본 접속 서비스는 모두 **IPv4 `0.0.0.0`**(PC의 모든 IPv4 인터페이스)에서 listen한다.

| 서비스 | 포트 | 기본 interface |
| --- | --- | --- |
| Telnet | TCP 8700 | `0.0.0.0` |
| Web | TCP 8701 | `0.0.0.0` |
| WebSocket | TCP 8702 | `0.0.0.0` |
| Telnet SSL | TCP 8703 | `0.0.0.0` |
| SSH | TCP 8704 | `0.0.0.0` |

같은 PC에서는 위 로컬 주소를, LAN에서는 `http://<서버의 LAN-IP>:8701/webclient/`를 사용한다. WebSocket은 현재 접속 hostname의 8702 포트에 자동 연결하며 IP를 고정하지 않는다. `ALLOWED_HOSTS = ["*"]`로 IP/hostname의 HTTP Host를 허용한다. `0.0.0.0`은 bind 주소이며 브라우저에 입력할 접속 주소가 아니다.

OS 방화벽이 허용하면 같은 LAN의 다른 장치에서도 접근할 수 있고 NAT/포트포워딩을 별도로 설정하면 외부 네트워크에도 노출될 수 있다. **8700 Telnet은 평문 프로토콜**이다. 최초 SSL/SSH 시작 시 생성되는 key/cert와 self-signed 인증서 정책, 로컬 전용 override는 [설치 안내](docs/installation.md#네트워크와-자동-생성-키)를 따른다. 방화벽·공유기 설정과 인증 정책은 서버 시작 명령이 변경하지 않는다.

setup은 비밀번호 접속이 비활성화된 로컬 admin 계정을 준비한다.
관리 기능이 필요할 때만 'uv run python scripts/dev.py admin-password'로 직접 비밀번호를 설정한다.
게임 테스트는 별도의 일반 탐사자 계정으로 진행한다.

## 명령과 도움말

`소지품`은 `가방`·`가진거`·`i`·`인벤토리`로도 입력한다. `상품`은 판매 목록, `도망`(`flee`)은 전투 이탈, `치료`(`힐`/`heal`)는 정신력을 쓰는 자신·같은 방 파티원 치료다. `붕대 사용`은 정신력 없이 붕대 하나를 소비한다. 의무관의 `진료`(`treat`)와 침대의 `휴식`(`rest`)은 기존 시설 서비스다. 액티브 방어와 응급처치 기술은 제거했으며 방어는 패시브 기술이다.

게임의 고정 **단축어**는 `단축어`로 조회하고 개인 **줄임말**은 `줄임말`로 관리한다. 방향은 시계방향 `ㅂ→북 · ㅂㄷ→북동 · ㄷ→동 · ㄴㄷ→남동 · ㄴ→남 · ㄴㅅ→남서 · ㅅ→서 · ㅂㅅ→북서`, 정보는 `상→상태 · 능→능력 · 기→기술 · 장→장비 · 소→소지품`이다. 옛 글로벌 `가`는 제거되어 개인 이름으로 등록할 수 있다. 단축어는 입력 전체가 일치할 때만 적용한다.

`도움말`은 여섯 분류의 짧은 안내다. `이동 도움말`·`전투 도움말`·`아이템 도움말`·`성장 도움말`·`교류 도움말`·`편의 도움말`에서 전체 분류를, `치료 도움말`·`상품 도움말`에서 개별 사용법을, `입력 도움말`에서 대상/선택자/관계/묶음 문법을 확인한다. `ㅂㄷ 도움말`은 이동 안내, `소 도움말`은 소지품 상세, `파티 도움말`은 파티 명령 상세다.

## 첫 사냥

장비는 자동 교체하지 않는다. 먼저 기존 무기를 해제하거나 방어구를 벗은 뒤 장착한다. ItemEntity backend의 동일 장비는 이름/이름 2로 구분하고 `<무기> 주무기`로 공격 무기를 선택한다. 기존 DB는 서버를 정지한 뒤 [명시적 migration](docs/item-migration.md)을 완료해야 하며 [장비 설계](docs/equipment.md)를 따른다.

광원·총기 기능은 [광원·총기 설계](docs/lighting-firearms.md)를 따른다. 일반 플레이는 ItemEntity 기반이다. 기존 DB를 로그인이나 명령 실행 중 자동 변환하지 않으며, 운영 migration/cutover 완료 전에는 서버가 시작을 거절한다. 아래 명령을 사용한다.

```text
손전등 2에 건전지 넣어
손전등 2 켜
손전등 2 확인
탐사카빈 재장전
탐사카빈에 카빈표준 2 장전
탐사카빈에서 탄창 꺼내
카빈표준 2에 카빈탄 넣어
카빈표준 2 채워
카빈표준 2에서 카빈탄 꺼내
```

각 손전등은 독립 잔량을 보존하고 하나만 켤 수 있다. 총기의 잔탄은 삽입된 탄창에만 저장하며 실제 발사에 1발을 사용한다. 빈 총기의 발사 행동은 공격 기회만 사용하고 정신력·cooldown은 사용하지 않는다. 성공한 전투 재장전도 기회 하나를 사용하며 무변경/실패는 사용하지 않는다. 탄창 분리·loose ammo 채우기/전량 꺼내기는 비전투에서만 가능하다. 탄창·탄약 상점, 표준 full 탄창을 포함한 총기 package와 적의 부분 장전 총기 드롭이 연결되어 있다. 최종 T0/T1/T2 장비·가격·획득처는 [최종 콘텐츠](docs/final-content.md)를 따른다.

명령은 `대상 + 행동` 순서로 입력한다. 예: `붕대 구매`, `절단마체테 무장`, `윤대장 대화`.
대상 이름의 공백은 허용하며, 행동 앞에는 공백을 둔다. `북`, `상태`, `강타`처럼 대상이 없는 명령은 그대로 사용한다.
기존 `공격 어린청소룡`처럼 행동을 앞에 쓰는 게임 명령은 지원하지 않는다. 별칭도 `어린청소룡 attack`처럼 뒤에 쓴다.

채팅은 `안녕하세요 말` 또는 `'안녕하세요`로 입력한다. 작은따옴표는 앞에 하나만 붙이며, 이후 내용은 명령어가 포함되어도 모두 채팅으로 처리한다.
예를 들어 `'안녕하세요 말`은 마지막 `말`까지 전송한다. 같은 장소에만 전달되며, 채팅 내용은 1~300자다.

```text
남
서
윤대장 대화
북
어린청소룡 공격
강타
시체에서 모두 가져
소지품
탐사용 벌목도 해제
절단마체테 무장
탐사대 작업복 벗어
강화방호조끼 착용
```

처치 시 경험치는 즉시 받지만 보급칩과 아이템은 `시체에서 모두 가져`로 회수해야 얻는다. 30초 후 시체의 남은 보급칩·아이템은 바닥으로 이동하며 `모두 가져`로 회수할 수 있다. 처치 후 120초간 배정 권한이 유지되고, 적은 45초 후 다시 나타난다.

새 탐사자는 출정 대기실에서 시작한다. `남`으로 본부 중앙 로비, `서`로 부두에 도착한다. 로비의 동쪽은 관리실, 남쪽은 휴게실이다. 2층은 보관·보급·정산, 3층은 의료, 4층은 교관 13명과 교육시설 6곳, 5층은 기본·전초·예약 장비/병기 시설이다. 윤대장은 부두에 남는다. 일반 `귀환`은 본부 옥상, 전투 패배는 3층 의무실로 이동한다. 최대 10칩 패널티와 체력 1·장비/경험치/아이템/진행 보존, 진료와 휴식, 새 로그인/재로그인의 출정 대기실 배치 및 서버 reload의 기존 위치 보존은 유지한다. [본부 전체 배치와 데이터 호환](docs/headquarters-redesign.md)을 참고한다.

1층 중앙 로비·2~5층 중앙 복도·옥상 중앙의 실제 `계단` 출구로 각 층 계단실에 들어간다. `위`/`u`·`아래`/`d`는 인접 계단실로 이동하고 `나가기`는 해당 층 중앙으로 돌아온다. 중앙의 `승강기` 출구는 기존 공용 Room으로 연결되며 내부 `1층`~`5층`·`옥상` 출구는 입력한 탐사자만 목적지로 이동시킨다. 공용 현재 층·운행·자동 하차 상태는 없다.

모든 Exit는 이름 또는 별칭만 입력할 때 이동한다. 추가 인자가 있으면 위치·방문 기록을 바꾸지 않는다. `북 보기`·`북 봐`는 기존 관찰 명령으로 유지한다. `출구`/`exits`는 어디서나 전투 중에도 실제 출구와 공개 가능한 목적지·이동 제한을 읽기 전용으로 보여준다. `출구 도움말`에서 조회 사용법을 확인한다. 3×3 나침반 중앙은 `o / ^ / v / X`이며 위·아래 중 하나라도 제한되면 전체 중앙 기호가 황색이다. 웹의 평면·수직·특수 출구 버튼은 같은 실제 출구 정보와 서버 명령을 사용한다.

일반 Exit 이동 알림은 transaction 성공 후 해당 시점의 시야/권한을 통과한 관찰자에게 한 번 전달된다. Bootstrap은 미관리 출구의 이름/별칭이 관리 방향이나 폐쇄 방향과 충돌하면 변경 전에 거절한다. 자세한 운영 확인은 [출구 소유권과 충돌 처리](docs/headquarters-redesign.md#관리-출구-소유권과-충돌-처리)를 따른다.

이동 방향은 `북(n)`·`북동(ne)`·`동(e)`·`남동(se)`·`남(s)`·`남서(sw)`·`서(w)`·`북서(nw)`다. 실제 출구가 있는 방향만 이동할 수 있다. 본부 옥상은 여덟 방향 모두 열려 있으며 각 주변 구역에서 반대 방향으로 중앙에 돌아온다. `북동 보기`/`ne 보기`는 이동 없이 정찰하고 `북동, 남서 해`는 왕복한다. Web 주변 행동의 3×3 compass는 출구가 적어도 중앙 위치와 빈 방향 공간을 유지한다.

### 여러 명령과 개인 줄임말

`해` 앞의 명령을 콤마로 구분하면 순서대로 실행한다. 두 명령 이상이어야 하며 앞 명령이 바꾼 위치·소지품을 다음 명령이 사용한다. 개별 게임 명령이 실패해도 계속하지만 잘못된 문법·순환 참조·확장 한도는 실행 전에 전체 거절한다. 콤마가 있는 `안녕, 반가워 말`과 `'안녕, 반가워`는 그대로 한 번의 채팅이다.

묶음 segment는 콤마 escaping/quoting을 지원하지 않는다. 콤마가 포함된 명령은 아래 `인사`처럼 단일 줄임말로 등록한 뒤 `인사, 상태 해`로 사용한다.

```text
상태, 장비, 소지품 해
줄임말 추가 점검 상태, 장비, 소지품 해
점검
줄임말 추가 인사 안녕, 반가워 말
줄임말
줄임말 삭제 점검
줄임말 모두 삭제
줄임말 모두 삭제 확인
```

줄임말은 캐릭터별로 저장하며 이름은 한글·자모·영문·숫자·밑줄 1~20자의 한 token이다. 기존 명령·별칭·시스템 단축어 이름은 사용할 수 없다. 이름을 단독 입력할 때만 확장하고 다른 줄임말도 재사용할 수 있다. 최대 10개 명령·중첩 5단계·확장 문자 합계 1000자이며 조건·반복·대기·인자 치환은 지원하지 않는다.

`줄임말 모두 삭제`는 요청만 만들고 삭제하지 않는다. **요청과 확인은 각각 별개의 입력으로 직접 실행해야 하며 묶음·개인 줄임말을 통한 간접 실행은 거절한다.** `줄임말 모두 삭제 확인`은 먼저 직접 삭제를 요청한 경우에만 동작한다. 간접 확인은 기존 요청을 소비하지 않는다. 60초 안에 목록이 그대로인 경우 한 번만 확인할 수 있으며 추가·교체·개별 삭제·로그아웃·서버 종료 시 요청을 취소한다. 사용법과 안전 계약·현재 한계·향후 후보는 [개인 줄임말과 묶음 명령](docs/command-shortcuts.md)에 있다. 게임 안에서는 `해 도움말`, `줄임말 도움말`을 사용한다.

### 대상 선택과 전리품 회수

번호 없이 입력하면 기본 대상 하나를 선택한다. 같은 이름이 여러 개면 `<대상> 2 <행동>`으로 두 번째를, `<대상> 모두 보기`로 같은 종류 전부를 살펴본다. 번호는 현재 방에서 보이는 순서로 정해지며, 객체가 사라지면 다시 붙는다. 공격·대화·조사·수리·무장·착용은 한 대상만 지정할 수 있다.

`봐`는 `보기`의 별칭으로 대상·번호·모두 선택에 동일하게 사용할 수 있다. `북 봐`/`n 보기`처럼 현재 출구를 살펴보면 이동 없이 인접 장소의 이름·설명과 적/NPC/시설/시체의 종류·수량을 관찰한다. 탐사자는 이름 없이 수만 보이고 HP·대상 번호·전리품·상자 내용·행동 안내는 보이지 않는다. 작은 기록/표식과 바닥 물건도 원거리에서는 숨긴다. 방향 관찰은 방문·임무·재생성/시체 만료를 진행하지 않는다. 실제 이동한 뒤 `보기`로 정밀한 대상과 물건을 확인한다.

장소 설명은 지형·건축·분위기·남은 흔적을 담고, 현재 적이나 시설의 존재·행동은 각 객체가 따로 표현한다. 원거리 객체 표시는 기본 숨김이며 NPC·보관함·큰 시설처럼 명시적으로 허용한 대상만 보인다. 보급상자·늪지 보급품·작은 기록/표식은 실제 방에 들어가야 식별할 수 있다. 진행 조건이 충족되지 않은 경계는 방향 관찰에서도 너머 장소와 객체를 숨기고, 조건 충족 후 정상 정찰을 허용한다. 정찰 차단 문구는 실제 진입문과 임무 보고 조건을 구분하며 이동 실패 안내는 그대로 유지한다.

```text
갈퀴사냥룡 공격
갈퀴사냥룡 2 공격
갈퀴사냥룡 모두 보기
시체 보기
시체 2 보기
시체 모두 보기
회수 부품 가져
회수부품 2 가져
회수부품 모두 가져
모두 가져
시체에서 회수부품 가져
시체에서 회수부품 모두 가져
시체에서 모두 가져
시체 2에서 모두 가져
모든 시체에서 회수부품 모두 가져
모든 시체에서 모두 가져
```

`시체에서`는 여러 시체가 있어도 기본 시체 하나만 선택한다. `시체 2에서`는 두 번째 시체, `모든 시체에서`는 모든 시체를 선택한다. 모든 시체를 선택하면 가져올 대상에도 `모두`를 붙여야 한다. 시체 번호는 적 종류별이 아니라 방 전체의 시체 순서다.

시체 상세 보기에는 현재 지정명과 `시체 2에서 모두 가져` 같은 회수 명령이 표시된다. 시체가 하나면 `시체에서 모두 가져`로 안내한다. 바닥 물건도 `회수부품 2 보기`로 살펴보면 해당 entry의 실제 회수 명령을 확인할 수 있다. 번호는 다른 시체나 물건이 사라지면 바뀔 수 있으며, 실행 시 현재 방의 순서로 다시 선택한다.

아이템은 번호 없이 또는 번호로 지정하면 한 개, `모두`를 붙이면 선택한 범위의 전체 수량을 회수한다. `전리품 모두`는 모든 아이템 종류이며, `모두 가져`는 `전리품 모두 가져`의 축약이다. 출처를 생략하면 바닥 전리품을 선택한다. 여러 시체를 회수할 때 다른 그룹의 보호된 물건은 남기고 회수 가능한 것만 배정자에게 지급한다. `전체 회수부품 가져` 같은 앞쪽 전체 선택 문법은 지원하지 않는다.

`친구이름 파티초대` → 상대의 `파티수락`으로 함께 사냥할 수 있다. `파티`, `파티거절`, `친구이름 파티제외`, `친구이름 파티장위임`, `파티탈퇴`를 지원한다. 기본 전리품 분배는 참여자 순번이며, 파티원 누구나 회수를 요청해도 아이템은 배정된 탐사자에게 들어간다. 일반 적은 다른 그룹의 공격을 거부하고 보스는 여러 그룹이 참여할 수 있다.

사냥으로 얻은 보급칩과 회수부품의 정산금으로 본부 5층 기본 병기점·장비점에서 장비를 구매할 수 있다.
'도움말', '임무', '지도'로 진행 방법을 확인한다. 상인은 본부 2층 보급품 상점과 5층 병기점·장비점, 진료·휴식은 3층 의무실에서 이용한다.
접속 준비, 전체 임무 경로, 기능별 정상 결과, 자동 테스트와 결과 기록 방법은 [테스트 안내](docs/playtest.md)에 있다.

## 화폐와 회수 자원 정산

보급칩의 단위는 **칩**이다. `상태`와 `소지품`은 `127칩`처럼 잔액을 표시하며 소지품이 비어도 잔액은 남는다. `칩 보기`/`보급칩 보기`로 화폐 설명을 확인한다. 칩은 일반 아이템이 아니며 보유 잔액으로 관리한다.

```text
철수에게 칩 줘
철수에게 20칩 줘
철수에게 칩 모두 줘
20칩 버려
칩 모두 버려
칩 가져
20칩 가져
칩 2 가져
칩 모두 가져
시체에서 20칩 가져
시체 2에서 칩 모두 가져
모든 시체에서 칩 모두 가져
```

수량 생략은 1칩이다. `20칩`은 금액, `칩 2`는 두 번째 회수 가능한 화폐 더미다. `모두`는 접근 가능한 전액이며 여러 시체를 선택할 때도 `칩 모두`로 지정한다. 0·음수·소수·잔액 초과는 거절한다. 전달은 같은 방의 지각 가능한 다른 비전투 탐사자에게만 가능하고 직접 버린 칩은 누구나 가져갈 수 있다.

적을 처치하기만 해서는 보급칩을 얻지 않는다. 보호 중 파티 시체의 칩을 회수하면 처치 당시 참여자의 몫을 함께 지급하며 회수 요청자가 독점하지 않는다. 자신의 남은 몫이 0이어도 원래 참여자는 다른 참여자의 남은 분배를 회수할 수 있다. 일부만 회수해도 남은 몫을 보존하고, 탈퇴·해체·가입 이후에도 기존 권리는 바뀌지 않는다. 공용 보스는 기여 그룹별 몫을 보호하며 보호 만료 후 남은 칩은 자유 획득이다. 시체에서 바닥으로 옮겨져도 남은 보호 기한과 몫을 유지한다.


보급칩은 유일한 구매 화폐다. 일반 회수부품은 탐사에서 얻는 경제 재료이며 정산·전달·공용/개인 보관에 사용한다. 발전기는 별도의 정비용 회수부품 3개로 수리한다. 정비용 부품은 제출 외 판매·정산·소각·이전이 불가능하다. 기존 보유 부품을 자동 환전하지 않는다.

본부 2층 중앙에서 `동` → `북`으로 자원 정산소에 도착한다. **자원 정산관**(별칭 정산관)에게 회수부품 1개당 10칩으로 정산한다.

```text
정산관 환율
회수부품 교환
회수 부품 교환
회수부품 10개 교환
회수부품 모두 교환
정산관에게 회수부품 10개 교환
```

수량 생략은 1개, `N개`는 정확한 수량, `모두`는 현재 소지품의 모든 회수부품이다. 정비용 회수부품은 정산 대상이 아니며 일반 회수부품과 별도로 보존된다. 정산·스택 판매·소각은 `N개` 수량을 지원하며, 이전·보관은 기본 1개/`모두` 문법을 사용한다. 현재 방의 관찰 가능한 정산관이 있어야 하고 안전·비전투 상태에서 이용한다. 대상 없는 입력은 정산관이 하나일 때만 자동 선택하며 여럿이면 이름·번호를 지정한다. 웹은 보급칩과 회수부품 자원을 구분하고 서버가 제공한 환율·모두 정산 버튼으로 같은 명령을 전송한다.

정산소에서 `남` → `서` → `승강기` → `5층` → `동` → `북`으로 기본 병기점에 들어가 `무기상 상품`, `절단마체테 구매`를 이용한다. 가격과 획득 경로는 [V1 콘텐츠](docs/final-content.md)를 따른다. 기술 학습 비용·패배 패널티·정산율은 유지한다.

## 본부 NPC 상점

- 2층 중앙에서 `북`: **보급관**의 보급품 상점. 탐사용손전등 35칩, 건전지 8칩, 붕대 10칩, 야전식량 5칩, 정제수 3칩.
- 승강기 5층 중앙에서 `동` → `북`: 기본 병기점의 **무기상**. T1 무기·방패·offhand·탄창·탄약을 판매한다.
- 5층 중앙에서 `서` → `북`: 기본 장비점의 **방어구상**. T1 착용 장비를 판매한다.
- 5층 서쪽/동쪽 끝 복도에서 `북`: **전초 장비고/병기고**. 전초 보급구역 출입증이 필요하고 T2 착용 장비 / T2 무기·방패·offhand·탄창·탄약을 판매한다. 남쪽의 다음 단계 시설은 출입증이 있어도 아직 폐쇄되어 있다.

```text
상품
보급관 상품
붕대 구매
보급관에게 붕대 구매
무기상 상품
절단마체테 구매
무기상에게 절단마체테 구매
방어구상 상품
방어구상에게 강화방호조끼 구매
```

현재 방에서 보이는 실제 상인이 안전·비전투 상태일 때 서비스를 제공한다. `상품`은 상인이 한 명일 때 자동 선택하고, 대상 없는 구매는 해당 물품을 파는 상인이 한 명일 때만 자동 선택한다. 여러 판매자가 같은 물품을 팔면 이름·번호를 지정한다. 각 상인은 자기 catalog만 판매하며 구매는 보급칩으로 1개씩, 재고는 무한이다. 부두에는 상인이 없어 상품 확인·구매를 이용할 수 없다. 웹 주변 행동의 상품/구매/가치/판매 버튼도 서버가 만든 동일 명령을 전송한다.

`절단마체테 가치` 또는 `무기상에게 절단마체테 가치`로 기준가와 매입가를 확인한다. `붕대 판매`는 1개, `붕대 3개 판매`는 3개, `붕대 모두 판매`는 소지한 스택 전부를 판매한다. 구매 목록과 매입 category는 별개여서 필드에서 얻은 정글장도도 기본 병기점에 판매할 수 있다. 사용 중인 장비는 먼저 해제해야 하며 동일 개별 장비는 `절단마체테 2 판매`로 선택한다. 일반 매입가는 가격의 절반 내림이며 explicit 매입가가 우선한다. 회수부품은 정산관 전용이고 임무 물품·출입증은 상점에 판매할 수 없다. 탄약은 9mm 12발·5.56mm 20발·7.62mm 8발 묶음으로 구매한다. 총기는 full 표준 탄창을 포함한 package로 구매하며, 탄창 판매가는 잔탄 가치를 포함한다.

## 출입증과 소각

통신탑 최종 보고에서 윤대장이 **전초 보급구역 출입증**, 깊은 밀림 최종 보고에서 선발대 길잡이가 **특수 보급구역 출입증**을 지급한다. 소지품에서 확인할 수 있고 파티원에게 공유되지 않는다. 완료 기록만으로 들어갈 수는 없으며 실제 출입증이 필요하다. 분실·소각 후 원래 발급자에게 대화하면 출입증만 무료 재발급받는다.

본부 2층 자원 정산소의 **폐기물 소각기**에서 물품을 폐기한다. 보급칩이나 탄약은 반환되지 않는다.

```text
붕대 소각
붕대 3개 소각
붕대 모두 소각
전초 보급구역 출입증 소각
전초 보급구역 출입증 소각 확정
```

출입증은 첫 명령에서 확인 안내만 나오고 정확한 `소각 확정` 명령으로 삭제한다. 임무 완료·보상은 유지되지만 출입 권한은 즉시 사라진다. 탄창이 꽂힌 총기는 먼저 탄창을 분리해야 판매·소각할 수 있다. 잔탄 탄창 자체는 소각하면 잔탄도 함께 소멸한다.


## 의료와 복귀

| 용어 | 역할 |
| --- | --- |
| 의료 | 관련 시스템·서비스·시설 전체를 포괄하는 분야 |
| 치료 / 힐 / heal | 정신력을 사용하는 플레이어 기술. 자신 또는 같은 방 파티원 대상 |
| 붕대 사용 | 붕대 하나를 소비해 HP 20 회복, 정신력 소비 없음 |
| 진료 / 휴식 | 의무관(`treat`) / 침대(`rest`)의 무료 시설 서비스 |
| 회복 | HP 또는 정신력이 증가한 결과 |

치료량은 자신의 최대 HP와 치료 Rank, 지혜 투자에 따라 증가하며 대상의 부족한 HP까지만 회복한다. 치료·호흡·붕대는 비전투에서 즉시 실행하고 전투에서는 다음 자동 공격 한 차례를 대신한다. HP가 가득하면 붕대를 소비하지 않는다. 숙련 시스템은 사용하지 않는다.

탐사 지역에서 비전투 중 `귀환`하면 본부 옥상에 도착한다. `승강기` → `3층` → `북`으로 의무실에 들어간다. `진료`/`의무관 진료`/`의무관에게 진료`, `휴식`/`침대 휴식`/`침대에서 휴식`을 사용한다. 의사·병상 별칭도 지원한다. 두 서비스는 무료이며 붕대·보급칩에 영향을 주지 않는다. 진료는 체력만 가득 채우고, 휴식은 체력과 정신력을 모두 채운다. 휴식은 두 자원이 모두 가득할 때만 거절한다.

현재 방의 관찰 가능한 의무관 또는 침대가 있어야 하며 안전·비전투 상태에서만 이용한다. 대상 없는 입력은 보이는 해당 객체가 하나일 때만 자동 선택하고 여럿이면 이름·번호를 지정한다. 웹 주변 행동도 서버가 제공한 같은 대상 명령을 사용한다. 패배의 자동 체력 1 복구는 이 두 서비스를 사용하지 않는다. 의무실에서 `남` → `승강기` → `1층` → `서`로 부두에 돌아갈 수 있다. 신규 시작·재로그인은 출정 대기실이며 살아 있는 세션의 서버 reload 복원은 기존 위치를 유지한다.

## 정신력과 자연회복

최대 정신력은 레벨 기본 정신력 + 지혜 투자×4다. Lv.10 이후 기본 성장률을 낮추며 Lv.133 기본 331, 지혜 MAX 시 411이다. 신규 탐사자는 40/40으로 시작하고 기존 v8 이하 프로필은 현재 최대치로 시작한다. 레벨 상승은 최대치 증가분만큼 현재 정신력을 올리며 지혜 배분은 최대치만 올린다. 정신력이 0이어도 현재 별도 불이익은 없다.

체력의 기본 회복은 비전투에서 분당 `2 + 최대 체력/60`, 정신력은 전투 중에도 분당 `4 + 최대 정신력/20`이다. 의무실은 체력 +6·정신력 +2, 본부 중앙 로비는 +2·+2, 폐쇄된 관리동은 +2·+1, 옥상과 주변 여덟 구역은 정신력 +2를 더한다. 장소 보너스는 비전투에만 적용한다. 생존모듈·신경안정칼라·의무전술벨트·재생모듈·정신안정모듈 등 실제 장착 장비가 회복 보너스를 제공한다. 범용 시간제 소비품 회복 buff는 아직 제공하지 않는다.

실제 수치는 고정된 10초 경계에서 정수만 회복하고 남은 시간·소수량은 보존한다. 이동·장비 변경·전투 시작만으로 즉시 회복하지 않는다. 로그아웃 위치의 보너스와 만료 전 효과는 오프라인에서도 계산한 뒤 로그인 시 출정 대기실로 이동한다. 피해 입은 적은 교전 종료 후 15초를 기다리고 분당 `8 + 최대 체력/15`씩 회복하며 즉시 가득 차지 않는다.

텍스트 prompt는 `[ 60/60 · 40/40 ] >` 순서로 체력·정신력을 표시한다. 현재 수치만 비율에 따라 초록·노랑·빨강·0의 강조 빨강으로 표시하며 Web의 HP·정신력·XP meter는 실시간 상태를 보여주고, prompt는 메인 텍스트의 스크롤 기록에 남는다. 명령 결과의 마지막에 한 번 표시하며, 빈 Enter로 현재 값을 다시 확인할 수 있다. 자동 전투 메시지마다 표시하지 않고 자연회복으로 실제 정수 자원이 바뀌면 새 prompt를 출력한다.

Web과 Telnet은 같은 서버 수치와 formatter를 사용하며 입력은 `[ 60/60 · 40/40 ] > 상태`처럼 prompt 오른쪽에 이어서 남는다. 비동기 메시지가 끼어 있으면 과거 prompt를 고치지 않고 최신 서버 값으로 새 입력 행을 만든다. 로그인은 방·환영 안내 뒤, 패배는 구조·손실·의무실 화면 뒤에 최종 prompt를 표시한다. 종료 때는 표시하지 않는다. 빈 입력은 명령 기록에 넣지 않고, 과거 로그를 위로 읽는 동안 새 prompt가 화면을 강제로 아래로 내리지 않는다. 저장과 출력 경계의 역할은 [프롬프트 lifecycle](docs/architecture.md#프롬프트-출력-lifecycle)에 설명한다.

## 성장과 재훈련

`능력`은 네 특성의 투자·남은 포인트를, `기술`은 여덟 기술 Rank와 남은 훈련을, `경험치`는 누적 XP와 다음 레벨 보상을 조회한다. 현재 기본 기술 MAX 합계에 따라 최고 레벨은 Lv.133이다. 모든 특성은 Lv.126에서, 모든 기술은 Lv.133에서 완성할 수 있다. 상세 공식과 대표 수치는 [성장과 전투 설계](docs/progression.md)를 따른다.

특성은 기본 10에서 각각 +20까지 투자한다. 기술은 모두 R1로 시작하고 레벨업마다 훈련 1회를 얻는다. 미사용 훈련은 `(레벨−1)−Σ(Rank−1)`로 계산한다. 훈련은 무료이며 담당 교관이 있는 안전한 방에서 비전투 중 이용한다.

| 본부 4층 교육시설 | 담당 훈련 |
| --- | --- |
| 훈련실 (서쪽 북) | 공격·강타·힘 |
| 생존훈련실 (서쪽 남) | 방어·체질·호흡 |
| 훈련관리실 (중앙 북) | 특성 재분배·기술 재분배·전체 재훈련 |
| 전술훈련실 (중앙 남) | 견제·지혜 |
| 사격장 (동쪽 북) | 사격·간파·민첩 |
| 의료훈련실 (동쪽 남) | 치료 |

진료와 침대 휴식은 본부 3층 의무실에서 이용한다.

```text
강타 배워
타격교관에게 강타 배워
힘 4 배분
근력교관에게 힘 4 배분
훈련관리관에게 기술 재분배
특성 재분배
전체 재훈련
```

담당 교관이 하나면 이름을 생략할 수 있고 여럿이면 지정해야 한다. 특성은 요청량 전체가 가능할 때만 적용하며 기술은 한 번에 Rank 1을 올린다. 재훈련은 해당 투자만 반환하고 현재 HP·정신력을 무료로 채우거나 cooldown을 초기화하지 않는다. Web 버튼도 서버가 제공한 같은 NPC 명령을 실행한다.

기존 캐릭터는 profile v10으로 변환한다. XP·장비·소지품·임무·발견·방문·보관·광원·파티 데이터는 보존하며 기존 숙련은 제거한다. 옛 기술은 비례 환산하지 않고 새 여덟 기술 R1로 초기화해 해당 레벨의 훈련을 다시 투자한다. 특성은 각 +20과 현재 레벨의 총 예산 안에서 보존한다. 기존 개인 줄임말의 붕대 행동·액티브 방어는 `붕대 사용`·`견제`로 옮기고 새 명령과 충돌하는 이름은 `_개인[번호]`로 보존한다. 절대시각 cooldown은 재접속·재훈련으로 초기화하지 않는다.

교관을 보면 담당 기술/특성과 훈련 입력을 확인할 수 있다. 현재 수치는 `기술`·`능력`에서 확인하며 재분배 결과는 선택한 특성/기술/전체 범위와 초기화 이후 사용 가능한 총량을 안내한다. 전문 교관은 직접 훈련만, 훈련관리관은 재분배만 제공한다.

간파와 견제의 재사용 대기는 각각10초다. 견제는 플레이어마다 같은 적에 하나씩 적용하고 참여자의 효과는 곱산으로 중첩한다. public 전투에 여러 파티가 참여해도 효과 수는 제한하지 않으며 최종 감소율만 일반56.95%·보스32.92%로 제한한다. 보스는 개별 효과를 절반으로 적용하며 적의 공격 한 번마다 모든 효과의 남은 횟수가1 줄어든다. 교전이 끝나면 효과가 사라져 도망 후 재교전에 이어지지 않는다. 정신력이 부족하면 기술명과 실제 필요량을 안내한다. 자세한 공식과 수명은 [성장 설계](docs/progression.md#공유-견제)를 참고한다.

고정 단축 입력은 `단축어`, 개인 설정은 `줄임말`에서 확인한다. `상`·`능`·`기`·`장`·`소`와 여덟 방향 초성은 입력 전체에만 적용한다.

### 물건 사용과 보관

`때려`는 `공격`의 별칭이다. `갈퀴사냥룡 2 때려`도 같은 번호의 적을 선택한다. 장비는 `절단마체테 해제`, `강화방호조끼 벗어`로 소지품에 남겨 둘 수 있고, 무기 없이도 기본 공격이 가능하다.

```text
붕대 버려
붕대 모두 버려
붕대 가져
탐사자에게 붕대 줘
탐사자에게 붕대 모두 줘
보관상자에 붕대 모두 넣어
보관상자에서 붕대 꺼내
개인 보관함에 강화방호조끼 넣어
개인 보관함 보기
개인 보관함에서 강화방호조끼 꺼내
```

본부 2층 중앙에서 `동` → `북`으로 자원 정산소에 도착한다. **자원 정산관**(별칭 정산관)에게 회수부품 1개당 10칩으로 정산한다.

물건 이전·장비 해제·음식/음료 사용은 비전투 중에만 가능하다. `줘`는 같은 방의 다른 비전투 탐사자에게만 가능하며 NPC나 자기 자신에게 줄 수 없다. 사용법은 `줘 도움말`, `넣어 도움말` 등에서 확인한다.

| 2층 보급품 상점 소모품 | 가격 | 사용 | 효과 |
| --- | ---: | --- | --- |
| 붕대 | 10칩 | `붕대 사용` | HP 20, 정신력 소비 없음 |
| 야전식량 | 5칩 | `야전식량 먹어` | 체력 12, 비전투 |
| 정제수 | 3칩 | `정제수 마셔` | 체력 6, 비전투 |

음식·음료는 한 번에 하나만 소비하고 회복량은 부족한 체력으로 제한된다. 체력이 가득 찼으면 소비하지 않는다. 배고픔·갈증·보관 용량 제한은 없다.

## 장비와 획득 경로

무기는 `무기이름 무장`(`wield`), 방어구는 `방어구이름 착용`(`wear`)으로 바꾼다. 공백이 있는 이름도 허용하며 기존 `equip` 별칭은 지원하지 않는다. `아이템이름 보기`와 `무장 도움말` / `착용 도움말`에서 확인할 수 있다. 소지품은 각 장착 상태와 주무기를 표시한다.

탐사용 벌목도와 탐사대 작업복으로 시작한다. 기본점은 T1, 전초 보급구역 출입증으로 들어가는 전초 병기고·장비고는 T2를 판매한다. 손·머리·목·몸·장갑·허리·다리·발·반지·장신구 슬롯을 사용하고 반지는 동일 정의 두 개도 장착할 수 있다. 자동 교체는 하지 않는다.

부서진 수송차에서 탐사인식표, 늪지 보급품에서 정신안정모듈을 한 번 발견한다. 재생모듈과 전술연산모듈은 사냥으로 얻는다. 능선포식자표식과 포식자비늘장식은 각 Boss 임무의 첫 최종 보고 보상이며 저장할 수 있고 판매·소각·양도·버리기는 금지한다.

모든 최종 장비의 슬롯·modifier·가격·획득처, 상점 catalog, 드롭과 적 수치는 [V1 최종 콘텐츠](docs/final-content.md)에 정리했다.

## 두 번째 탐사 지역

통신탑 복구 임무를 마치고 윤대장에게 보고하면 능선 북쪽에서 **깊은 밀림**으로 들어갈 수 있다. 밀림 입구의 선발대 길잡이에게 의뢰를 받고 관측소의 관측 표식과 수몰 도로의 수위 표식을 조사한다. 수위 표식 아래에서 임무 전용 밀림 신호전지를 한 개 확보하고, 거목 군락의 신호 장치에 사용하면 전지가 소비되며 연구구역 문이 열린다. 문을 열기 전 전지를 잃었다면 수위 표식을 다시 조사해 한 개를 되찾을 수 있다. 보스를 처치한 뒤 길잡이에게 보고한다. 늪지 샛길에는 선택 보급품과 강한 사냥감이 있다.

```text
[탐사대 전초구역]
     탐사대 부두
          │
   바람 부는 초지 ─ 부서진 수송차
          │
 발톱 자국 오솔길 ─ 관리동 ─ 발전실
          │
     물안개 습지
          │
     통신탑 능선
          │
[깊은 밀림]
                         포식자 둥지
                               │
                         연구구역 외곽
                               │
          버려진 관측소 ─ 거목 군락
                │               │
늪지 샛길 ─ 밀림 입구 ─ 수몰된 도로
                │
           통신탑 능선
```

```text
선발대 길잡이 대화
관측 표식 조사
수위 표식 조사
신호 장치 조사
밀림의포식자 공격
선발대 길잡이 대화
```

첫 지역의 Room ID와 기존 장비 획득 경로는 유지한다. 새 지역의 보스도 혼자 공략할 수 있으며 파티와 공용 기여 보상·시체 전리품 규칙을 함께 사용한다.

## 개발

일반 실물 아이템의 runtime SSOT는 ItemEntity, 실물 전리품 권리는 LootClaim, 보급칩 전리품은 CurrencyLoot/CurrencyLootShare, 접근 권한은 Credential ItemEntity다. 새 빈 DB는 native로 직접 시작한다. 구버전 DB는 [명시적 호환 migration](docs/item-migration.md)이 필요하며 로그인 자동 변환·dual-write·legacy gameplay fallback은 없다. [아이템 구조](docs/item-entities.md)와 [현재 architecture](docs/architecture.md)를 참고한다.

```sh
uv run python scripts/dev.py check
uv run python scripts/dev.py test
uv run python scripts/dev.py reload
uv run python scripts/dev.py stop
```

CSS·JavaScript·글꼴 변경 후에는 'game' 폴더에서 'uv run python -m evennia collectstatic --noinput'을 실행하고 브라우저를 새로고침한다.
테스트는 전용 메모리 DB와 빠른 비밀번호 해시를 사용하며 플레이 DB·운영 인증 설정을 변경하지 않는다.
통합 테스트는 CPU 수에 따라 최대 4개 프로세스로 실행한다. `uv run python scripts/dev.py test --parallel 1`로 직렬 실행할 수 있다.
관련 통합 검사만 실행하려면 `uv run python scripts/dev.py test tests.test_headquarters --parallel 2`처럼 테스트 경로를 지정한다. 경로를 생략한 기본 명령은 순수·통합 검사를 모두 실행한다. `--reverse`는 실행 순서를 뒤집어 테스트 격리를 확인한다.
게임 규칙 테스트와 Evennia 통합 테스트를 GitHub Actions에서도 실행한다. CI는 PR과 main push에서 검사하며 통합 테스트는 2개 프로세스를 사용한다.

실제 서버·WebSocket·scheduler 연결은 실행 중인 개발 서버 없이 검사한다:

```sh
uv run python scripts/dev.py smoke
uv run python scripts/dev.py smoke-full
```

`smoke`는 단축 타이머를 쓰는 Quick Live Smoke로 PR/main CI에서도 실행한다. `smoke-full`은 production 타이머로 시체 30초·적 재생성 약 45초·전리품 보호 120초를 실제로 확인하는 수동/closeout 검사다. 두 명령 모두 매 실행마다 `work/smoke/<mode>-<run-id>`에 새 SQLite DB와 일반 fixture 계정 3개를 만들고 독립 포트의 Evennia Portal/Server를 시작·종료한다. 플레이 DB와 사용자 PostgreSQL 설정은 사용하지 않는다.

공개 가입 없이 fixture를 실제 인증하여 파티·공동 전투·점유·전리품 배정·시체/바닥 전리품·보호 만료·재생성·옥상/승강기/무기상 구매·재접속을 검증한다. 가입 throttle과 610초 대기는 gameplay의 선행 조건이 아니며 production 가입 제한은 그대로다. 성공 시 실행 디렉터리를 삭제하고, 실패 시 프로세스를 종료한 뒤 DB/로그 경로를 출력한다. CI 실패 단계는 로그 tail만 출력한다(DB 제외). 저장소 Actions 허용 목록을 유지하여 artifact 업로드 action은 사용하지 않는다. 공개 가입 정책은 별도 auth/registration 검사, 화면·IME는 별도 브라우저 검증 범위다. Full은 본부 전체 서비스, 실제 패배/회복, 두 임무와 두 보스의 최종 보고, 같은 DB의 Portal/Server 재시작·재로그인까지 연결한다. Full fixture에는 본부 거래·두 보스의 붕대 재충전용 준비금(검증가 350칩), 정산용 일반 회수부품 10개와 패배용 낮은 HP를 준비한다. 신규 계정 초기 자금이나 밸런스 검증 기준과 구분하며 정비부품·임무·구매·처치 결과는 실제 명령으로 만든다. 상세 계층·타이밍·실행 기록은 [테스트 안내](docs/playtest.md#격리형-실제-서버-검사)를 따른다.

### 탐사 기록과 정보 조회

Room은 눈앞의 대상과 실제 출구를 문장과 방향도로 보여줍니다. `<대상> 보기`로 설명과 가능한 행동을 확인하고, `도움말`에서 분류별 명령을 찾고, `공격 도움말`처럼 `명령이름 도움말`로 설명·사용법·별칭을 확인할 수 있습니다. 소지한 장비도 `절단마체테 보기`처럼 살펴볼 수 있습니다.

Room 본문과 세계 사건은 자연스러운 문장으로 표현합니다. SURROUNDINGS와 버튼은 빠른 상태 확인과 조작을 위해 `시체 1 · 갈퀴사냥룡의 시체` 같은 compact 표기를 유지합니다. 상세 보기는 남은 물건·권한과 실제 실행할 수 있는 명령을 안내합니다.

`상태`, `능력`, `경험치`, `기술`, `장비`, `소지품`, `상품`, `임무`, `파티`는 `[제목]`과 짧은 행으로 구성한 정보창으로 표시합니다. `능력 도움말`에서 특성 효과를 확인할 수 있습니다. 적·NPC·물건·명령·전리품은 의미별 색으로 구분하지만 로그의 단어는 클릭하는 링크가 아닙니다. 빠른 조작은 기존 SURROUNDINGS 버튼을 사용하세요. [색상과 출력 구조](docs/architecture.md#텍스트와-의미별-색상), [화면 검증 절차](docs/playtest.md#텍스트-인터페이스-확인)를 참고하세요.


## 동적 환경

데스크톱 FIELD GUIDE의 `환경 확인` 버튼도 같은 `날씨` 명령을 실행한다. Room에는 지속적인 지형·습기·누수 흔적을 기록하고 현재 안개·비·빛은 Environment만 표현한다. 웹 시각/시간대는 계속 갱신하지만 ambient 알림은 해당 장소의 환경 문장이 실제 달라질 때만 출력한다.

`날씨` 또는 `환경`으로 현재 장소의 게임 시각·시간대·날씨·달(밤)·밝기·시야를 확인한다. 실제 1분은 게임 4분이고 하루는 실제 6시간이다. 새벽 05–07시, 낮 07–18시, 해질녘 18–20시, 밤 20–05시다. 달은 게임 28일 주기로 삭·반달·보름달을 순환하고 밤의 자연광에만 기여한다.

전초구역과 깊은 밀림은 같은 `island` Weather Zone의 맑음·흐림·비·폭우·안개를 공유한다. 날씨는 현실 시간으로 각각 20–40/15–30/10–25/5–15/10–25분 동안 유지하며 현재 상태에 맞는 가중 전이를 사용한다. 실내에서는 밖의 날씨와 실내 밝기를 구분한다. 시간대나 날씨가 바뀌어 해당 장소의 환경 표현이 달라지면 접속한 탐사자에게 문장을 한 번 보내며, 재시작 중 지나간 사건은 재생하지 않는다.

Room의 정적 환경 설명 다음에 현재 환경 1–2문장, 방향도, 기존 객체 묘사가 나온다. `북 봐`에도 목적지 환경을 표시하지만 잠긴 진행 경계의 내부 정보는 계속 숨긴다. 웹 상단의 `08:00 · 맑음 · 낮 · 밝음`도 서버가 계산한 동일 관찰 시각의 값이다. 밝기와 시야는 실제 객체 식별에 적용된다. 환경 시야와 손전등을 반영한 현재 시야를 구분하며, 어두울 때도 이동 방향과 큼직한 시설은 인지할 수 있다. 이미 교전 중인 상대는 계속 추적한다. LOS·은신·원격 행동은 구현하지 않는다.


### 탐사 광원과 시설 조명

`부서진 수송차`의 `비상장비함 조사`로 탐사용손전등 하나와 건전지 두 개를 탐사자마다 한 번 받는다. 어둠 속에서도 비상장비함은 발견할 수 있다. 본부 2층 보급관에게 탐사용손전등은 35칩, 건전지는 8칩에 구매하고 늪지 보급품에서도 건전지 두 개를 받는다.

탐사자는 `손전등 확인`으로 상태를 보고 `탐사용손전등에 건전지 넣어`로 전원 하나를 삽입한 뒤 `손전등 켜`/`손전등 꺼`를 사용한다. Light Source와 Power Source는 별개이며 호환 타입과 실제 사용 용량은 아이템 metadata가 정한다. 건전지는 켠 동안만 30분을 제공한다. 전원이 남아 있으면 새 전원은 넣을 수 없다. 로그아웃하면 자동으로 끄고 잔량을 보존한다. 각 손전등 Entity는 독립 잔량을 보존하며 이동 시 OFF/참조 정산을 적용한다. 한 번에 휴대 광원 하나만 켤 수 있다.

`손전등 보기`는 설명·현재 상태·전원·잔량과 사용법을 함께 보여준다. `손전등 확인`은 같은 상태 계산으로 빠르게 조회한다. 방 안내도 실제 보이는 대상을 따르므로 어두운 수송차에서 `비상장비함 조사`는 남고 작은 보급상자 안내는 광원으로 식별한 뒤 나타난다. 시설 조명은 자연광보다 강할 때 환경 문장에서 강조하며, 맑은 낮의 부두는 낮빛을 표시한다. 공용 전력은 버전이 있는 별도 저장 state로 보존한다.

손전등은 현재 방 시야를 최대 두 단계, 인접 방향 정찰은 한 단계 개선한다. 환경 자체의 밝기는 바꾸지 않으며 view lock과 원거리 비공개 정책을 우회하지 않는다. 작은 표식과 바닥 물건은 좋은 시야에서, 일반 적·시체는 보통 이상 시야에서 식별한다. 시체 내부의 작은 전리품을 살펴보거나 회수할 때도 좋은 시야가 필요하다. 부두에는 상시 캠프 조명이 있고 발전기를 복구하면 관리동과 발전실의 공용 조명이 켜진다. 다른 탐사자의 개인 임무 조건은 바뀌지 않는다.

수송차 보급상자는 캐릭터당 한 번 붕대 2개·탐사인식표 1개를 지급한다. 발전기 미수리 상태에서만 정비용 회수부품을 기존 보유량 포함 총 3개까지 보충한다. Migration에서 이미 받았다면 중복 지급하지 않고, 발전기 수리 완료 후에는 지급하지 않는다. 일반 회수부품은 지급하지 않는다.
